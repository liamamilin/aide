日期：2026-09-13。状态：D00–D12 已完成代码、自动化和本机候选包验收，`1.5.0` ad-hoc arm64 候选已生成；真实桌面与分发人工门槛仍保留。最新证据见[开发进度](开发进度.md)。前置评估：[项目现状](项目现状与下一步计划-2026-09-13.md)。产品扩展另见[新功能开发计划](新功能开发计划-2026-09-13.md)。

## 1. 目标与交付边界

- **M1 / 建议 v1.4.1**：请求结果正确归属；停止、切换、退出不造成失控任务或界面卡住；服务检查异步；现有主题修复完整；构建版本统一。
- **M2 / 建议 v1.5**：图片可验证、可恢复、可清理；模型能力可见；历史可完整浏览；窗口状态可恢复。
- 每个里程碑独立验收和发布。截图 OCR、快捷动作、知识库等由下一份计划管理，不挤入本轮。
- 沿用 PyQt5、Ollama、SQLite。按职责提取必要模块，不同时重写全部 UI 或迁移框架。

## 3. 请求与数据契约

### 请求生命周期

`idle → preparing → streaming → succeeded / failed / cancelled`。取消可发生在 preparing 或 streaming。资源回收单独跟踪，不允许 UI 因等待回收继续锁住输入。

拟议 `RequestContext`：

| 字段 | 作用 |
|---|---|
| request_id | 每次生成唯一，拒绝过期回调 |
| conversation_id | 提交前固定，不从当前窗口临时读取 |
| agent_id、prompt_snapshot | 固定本次角色，切换 Agent 仅影响后续请求 |
| model、base_url、options_snapshot | 固定模型、服务地址和生成参数 |
| message_ids、attachment_ids | 固定实际发送的上下文来源 |
| created_at | 诊断耗时，禁止用它代替唯一 ID |

拟议 `StreamEvent`：包含 request_id、kind、text、error_code；kind 为 thinking、content、complete、error、cancelled。结束事件只能生效一次；Qt 的网络 error/finished 等重复信号不能造成重复保存。

明确行为：

- 成功答案只写入绑定会话；错误文本作为错误状态展示，不作为正常助手答案加入上下文。
- 用户手动停止时保留可复制的部分输出并标明未完成；M1 暂不把未完成输出加入后续推理上下文，也不承诺重启恢复它。
- 新建或加载历史先使旧请求失效，再切换视图。迟到的旧输出不渲染、不写入任何新会话。
- 生成中切换模型/Agent 只影响下一次请求，当前气泡显示提交时的模型/角色。
- 用户消息保存成功后重试应复用其 ID；保存失败时保留输入与附件，不重复插入用户消息。
- 成功内容若保存失败，保留界面内容并提示“未保存”，不伪装成生成失败或丢弃文本。

### 拟议模块边界

| 模块 | 职责 | 不承担 |
|---|---|---|
| `llm/events.py` | 请求/事件/错误类型 | UI、数据库写入 |
| `llm/transport.py` | 建连、流读取、取消、超时 | 会话选择、控件状态 |
| `services/request_coordinator.py` | 请求归属、终态、失效与回收 | 气泡布局 |
| `services/model_service.py` | 模型列表、能力缓存、连接状态 | 静默改动用户选择 |
| `services/attachment_service.py` | 图片校验、暂存、引用、回收 | 自动读取其他目录 |
| `main.py` | 组合服务、绑定信号、窗口入口 | 继续堆积独立业务逻辑 |

完成标准：可以明确区分本轮新增与已有改动；当前 195 项测试是起点，数量不作为质量目标。

### D01：结果事件与错误边界

- 涉及 `main.py:StreamingChatWorker`、`llm/chat_client.py`，提取公共事件类型。
- 以显式 error 事件判失败，移除“无法”等正文前缀判断。
- 区分连接失败、HTTP 错误、超时、流协议错误、图片预处理失败、用户取消；错误码稳定，提示文字独立。
- 包住图片编码和建立流之前的异常；处理 HTTP 200 内的服务端错误对象、无结束标记的意外断流。
- 请求参数在提交时取快照，生成中修改全局 config 不影响本次请求。

验收：正常“无法判断……”被成功保存；任意错误文本均失败；重复结束事件只触发一次；缺失图片使输入恢复且未启动推理。

### D02：可取消流式传输

状态：已完成代码与自动化验收。实现位于 `llm/qt_stream.py`、`llm/streaming_worker.py`；连接/首次写入预算默认 10 秒，收到上传进度或响应头后使用快照中的空闲超时。Qt 5 的第一阶段包含首次请求写入；详细语义、254 项测试证据与停止测量见开发进度。

- 先用不超过 0.5 人日验证 QtNetwork 方案：`QNetworkAccessManager` 发起请求，增量消费响应，在对象所属线程取消；耗时图片处理仍在后台。
- Qt 的 `QNetworkReply.abort()` 会中断连接并触发 finished，因此适配器必须将取消单独归类并去重结束事件。[Qt 官方说明](https://doc.qt.io/archives/qt-5.15/qnetworkreply.html#abort)
- 增量缓冲 UTF-8/换行 JSON，覆盖一个事件跨多个网络包、多个事件同包、最终无换行等边界。
- 设置独立连接/空闲超时；保留 50ms UI 批量刷新，不为每个字节重渲染。
- 若 QtNetwork 验证失败，记录原因与替代传输决策；不能以跨线程强制终止或仅隐藏停止按钮交付。
- 验证的是客户端取消与资源释放；服务端是否即时停止推理需真机测量，不能直接由连接关闭推断。

验收：用本地假服务模拟迟迟不返回 token，取消后控件恢复；请求终态唯一；本地计时目标为停止后 200ms 内 UI 有反馈，网络慢不影响该目标。真实模型性能另测。

### D03：控制器集成与退出

状态：已完成代码与自动化验收。D02 提前完成的即时停止与本包的加载/删除隔离、异步退出、截图取消和草稿回滚已合并验证；最终证据见开发进度。

- 所有 chunk/done 保存和渲染先检查 request_id，保存目标取 RequestContext。
- 新建、加载历史、删除当前会话、停止、退出共用失效/取消逻辑；截图任务同样参与退出协调。
- 移除主线程 `wait(5000)`；异步等待完成和清理引用，Qt 对象在所属线程释放。
- 退出先停止接收新事件，取消定时器、HTTP 和截图子进程，待任务结束再关闭应用；不得删除仍运行的 QThread。
- 修复发送失败后输入回填与 `_on_send()` 清空顺序，避免恢复好的草稿又被清除。

验收：A 会话生成时进入 B，A 迟到结果不出现在 B；停止后立刻新请求不会被旧 done 清空；删除当前会话后没有外键写入错误；退出后没有遗留本次启动的任务。

### D04：服务检查异步化

状态：已完成代码与自动化验收。桌面入口统一使用 `llm/service_checks.py` 的 QtNetwork 异步检查器；同步 `list_models()` 与 `check_for_update()` 只作为兼容 API 保留。模型缓存、状态显示、地址切换和启动提示的验证证据见开发进度。

- 打开窗口先使用缓存并立即显示，再更新模型列表；欢迎、模型检查、更新检查均不阻塞 UI。
- 状态区分：检查中、在线且有模型、在线无模型、离线、返回格式错误。失败不能被当作“没有安装模型”。
- 缓存以服务地址为键；切换地址后取消或丢弃旧请求，用序号拒绝乱序结果。
- 模型存在时保留选择；消失时显示回退信息，能力未知不视为不支持。
- 同一检查去重；窗口隐藏时按策略停止 UI 探活，重新显示恢复；取消不重复弹错误框。

验收：模拟 5 秒延迟时仍可移动、输入；服务地址 A/B 连续切换只采用 B 的结果；离线缓存模型不会被误报为在线可用。

- 截图结果区分用户取消、权限不足、超时、命令错误；`_on_screenshot_failed` 不再对所有错误显示权限未授权。

## 5. M2 详细工作包

### D08：附件生命周期

状态：已完成代码与自动化验收。实现采用 `attachments`/`message_attachments`、相对受管路径、原子写入、三态回收与运行请求临时占用；旧 JSON 原位兼容，缺图单独标注。详细证据见开发进度中的 D08 完成检查点。

1. 保存前验证真实解码、像素尺寸、文件大小与数量；第一版建议上限 4 张/条、20MiB/张、40MP/张，均为待样本验证的产品默认值。
2. 提交前在后台生成适合推理的副本，建议最长边 2048；保留原图用于查看，文字截图经验证必要时允许更高质量。界面显示压缩结果。
3. 状态区分暂存、已引用、待回收。移除草稿附件可回收；会话删除后，仅回收没有其他引用且不被运行请求使用的受管文件。
4. 文件写入和 DB 事务无法整体原子化：先暂存并原子改名，再提交引用；中断后通过待回收队列/启动扫描修复。删除失败可重试，不影响其他历史。
5. 老绝对路径记录懒迁移或批量迁移，缺图标注，不让整个会话无法打开；共享路径需去重引用。

验收：损坏/超限文件得到明确反馈；取消发送、删除会话后无永久孤立文件；共享图片不会提前删除；源文件与用户自行选择的外部文件不被清理。

### D09：模型能力

状态：已完成代码与自动化验收。当前模型通过异步 `/api/show` 检查图片能力，结论绑定服务地址、模型和 digest；界面显示三态并在发图前执行相应流程。本机真实 Ollama 的 6 个模型已完成只读兼容验证。

- 从模型详情读取能力，使用“支持/不支持/未知”三态；按地址、模型与版本信息缓存并失效，避免每次发图遍历所有模型。
- Ollama 模型详情接口列有 capabilities，可作为能力展示的输入，具体服务器/模型仍需兼容性验证。[Ollama 官方说明](https://docs.ollama.com/api-reference/show-model-details)
- 已知不支持图片时阻止直接发图，提供选择本地视觉模型；未知时说明未确认并允许用户决定是否尝试。未经确认不自动换模型或下载。
- thinking 参数按能力和用户偏好提交；不凭模型名字符串推断能力。

验收：文本模型、视觉模型、未知模型三种场景均可完成合理流程；连接错误与能力未知分开提示。
