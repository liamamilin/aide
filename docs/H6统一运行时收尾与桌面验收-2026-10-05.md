# H6 统一运行时收尾与桌面验收

更新日期：2026-10-05。候选版本仍为 `1.5.0`。接续 [H5 工具入口](H5显式工具任务入口-2026-10-05.md)，本阶段清理兼容代码并补 Action 重试回归，不增加工具或扩大模型准入。

## 执行路径收尾

所有普通聊天、Action、普通重新生成和工具重新执行直接创建 `RunWorker`，由 `RunLoop` 调度，`QtChatTransport` 负责模型 HTTP。普通聊天和 Action 是空工具、单轮情形。没有第二套聊天网络发送、取消或持久化实现，也没有旧 Worker 对照开关。

本轮删除：

- `llm/streaming_worker.py` 中 `StreamingChatWorker` 名称别名，所有产品与测试引用迁移到 `RunWorker`。
- 产品没有调用者的 `ChatClient.chat`、`chat_stream`、`ChatResponse`、`ChatStream` 以及相应 requests 流式收尾代码。
- 旧的 `chunk(str)` / `thinking_chunk(str)` 信号，统一使用包含 run / step / request / conversation / seq 身份的事件。

`ChatClient` 保留不可变请求快照、消息/图片准备及模型列表辅助函数；不发送聊天请求。H0 的独立行为验证探针仍保留，属于准入工具，不是应用聊天路径。旧同步客户端测试迁移到真实 Qt Worker，覆盖分块、思考、非法响应、空响应、超时、断连和未授权工具；依赖 requests 专有迭代器关闭行为的测试随旧实现删除，连接释放由 Qt 真实 HTTP 断连回归验证。

## 修复动作重新生成

原实现只从回答快照恢复 `origin=action` 和 action_id，后续却使用当前可见 Agent 的提示词及模型配置。尤其在“当前对话”中执行翻译后重试，界面 Agent 可以仍是通用助手或代码专家，导致动作规则和动作 profile 丢失。

现在通过保存的 action_id 重新构建动作计划，解析动作绑定 Agent、动作指令、动作 profile 及继承关系，再创建无工具单轮 Worker。当前对话保留原会话和可见 Agent；专用对话仍沿用动作 Agent。不重复保存用户材料，不把前一次答案或旧工具结果放进该轮重试输入。

重试采用**当前保存的动作定义和配置**，与当前配置下重试的既有行为一致；运行启动后使用不可变快照。若修改动作指令，再次生成会使用修改后的指令。动作已隐藏或历史缺失 action_id 时明确提示并停止，不悄悄退化为聊天。此轮没有保存额外的原始系统提示词副本，也没有新增任意动作类型：所谓自定义动作测试指的是现有四个动作的自定义指令/绑定配置。

另修复图片重新生成按顶栏全局模型检查能力的问题，改为检查实际解析出的模型。模型不支持图片时明确阻止并显示该模型名称，不会因全局模型支持就把图片交给不支持的配置模型。
