# 搜索凭据跨构建稳定修复

日期：2026-10-06。App 重建后已存密钥无法读取的问题已修复；当前构建的 Parallel / Exa 均已通过正常系统授权、后台无提示读取及冻结 27B 真实搜索完整验收。

## 原因与方案

现有证书是本地自签名证书，主应用没有 Apple Team ID。即使应用标识和证书不变，文件型钥匙串的 Partition ACL 仍可使用代码 CDHash 限制访问；重建改变该值后，旧授权不能匹配。两家服务此前已返回 HTTP 200，最新冻结包失败发生在读取密钥阶段，尚未发出请求。[Apple 的分区身份实现](https://github.com/apple-oss-distributions/Security/blob/main/securityd/src/clientid.cpp)与[本机只读证据](harness-h6/keychain-partition-mismatch-2026-10-06.json)支持此结论。

新增原生 `AIDESearchCredentials` 助手，以同一证书签名并复用相同可执行文件。冻结 App 的读取、保存、删除全部交给该助手；普通重建主应用时不重签助手。深度签名完成后安装助手，再只签主应用封装，避免助手 CodeDirectory 改变。签名助手位于 Contents/Helpers，完整性清单位于 Contents/Resources。

现有服务名和 parallel / exa 账户保持原样，不迁移到明文文件，不自动改 ACL、分区列表、钥匙串密码或已有密钥。新助手首次访问旧条目仍遵循系统授权。

## 使用方式

本机两家密钥当前均已完成连接，使用最新 App 即可。以下步骤用于首次连接新助手或新密钥：打开最新构建 App → 设置 → 联网搜索，选择 Parallel，点击“连接钥匙串”；系统询问 `AIDESearchCredentials` 访问对应密钥时，选择“始终允许”。切换 Exa 后同样连接一次。无需重新填写已有密钥。

该入口不联网、不计费、不调用模型。授权后另起一个无交互进程复核，只有持久访问通过才显示“已连接”。只选“允许一次”不能通过该复核。缺少密钥时提示填写后保存。

后台搜索禁止钥匙串交互，读取最多 6 秒，保留任务截止与取消控制。显式连接最多 120 秒，可停止；关闭设置页会取消，运行中的线程保持到结束。设置页“测试搜索”与免费连接检查分开；测试搜索仍可能按供应商计费。

## 调用约束

助手验证真实父进程 PID、应用标识 `com.milin.ai-desktop-assistant`、签名证书叶指纹与严格代码有效性。只接受 stdin/stdout 管道、固定两个供应商、固定钥匙串命名空间及有限长度 JSON，不提供任意钥匙串查询。正常 Python / 未受信任程序不能作为调用方。

密钥不写命令行、日志、设置或验收报告。主应用校验清单中的助手 SHA-256，损坏时失败，不退回主应用直接读密钥。旧冻结 `--search-credential-read` 导出入口已禁用；新诊断仅返回布尔状态。测试 CRUD 使用独立 fixture 命名空间和虚构值，完成后删除。

## 长期边界

普通主应用代码变化不会改变助手身份。修改助手本身、升级其编译器/SDK、替换签名证书，或更换安装位置可能仍需正常重新授权，应作为显式升级验收项；不能承诺任意系统更新永不影响权限。无证书的 ad-hoc 包不提供凭据助手，联网搜索需证书签名构建。正式发布可再采用 Developer ID / Team ID 与公证。
