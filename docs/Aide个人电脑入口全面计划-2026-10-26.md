# Aide 个人电脑入口：目标回顾与全面计划

日期：2026-10-26。状态：计划，未实施。前置文档：[设计草案](Aide个人电脑入口设计-2026-10-26.md)、[开发计划（M1–M4、P1 进度）](Aide个人电脑入口开发计划-2026-10-26.md)。

## 1. 目标

Aide 是 macOS 的个人智能操作入口：用户说出想做什么，Aide 负责寻找、打开、操作，最后把结果呈现出来。能直接调用系统接口的事不让模型去模拟鼠标；只有没有接口时才用界面识别。能力按 Find → Open → Operate → Automate 逐步增强。

**验收标准就是原始目标里的六个场景，加上用户实机试用时失败的两句话：**

| # | 场景 |
|---|---|
| S1 | 找一下我上周写的产品方案 |
| S2 | 打开我那个视频制作项目（在指定开发工具中） |
| S3 | 打开备忘录，把刚才的想法记下来 |
| S4 | 把下载文件夹里的 PDF 整理一下（预览分类后执行） |
| S5 | 帮我把两个窗口并排放好 |
| S6 | 帮我完成这个软件里的操作（识别界面、执行、检查结果） |
| F1 | “帮我看下备忘录有多少条”（实机失败） |
| F2 | “把刚才那条备忘录取消掉”（实机失败） |

## 2. 现状：逐场景，标明证据类型

证据类型：**实机**＝用户在真实桌面试过；**真模型**＝真实 9B 模型加模拟工具结果；**离线**＝只有离线测试。

| 场景 | 现状 | 证据 | 缺口 |
|---|---|---|---|
| 打开应用（打开备忘录/微信） | 可用 | 实机 | 复杂说法依赖触发开关，见 3.1 |
| S1 找文件 | 只能按名称匹配 | 真模型（整句查询会搜不到） | 无时间过滤（上周）、无内容匹配、无最近使用排序、无分词重试 |
| S2 视频项目 | 未做 | — | 没有“项目”概念，没有用指定应用打开 |
| S3 记想法 | 新建笔记可用 | 真模型；实机未确认写入 | 新建后不返回条目标识，“刚才那条”无法指代 |
| F1 笔记数量 | 做不到 | 实机 | 没有读取/列出/搜索笔记的工具 |
| F2 取消笔记 | 做不到 | 实机 | 没有修改/删除工具，也没有通用确认机制 |
| S4 整理 PDF | 未做 | — | 无计划→预览→确认→执行，无回收站与撤销记录 |
| S5 并排窗口 | 代码与离线测试完成 | 真模型；**实机未验证** | 本进程无辅助功能权限，窗口列表曾返回空 |
| S6 软件内操作 | 未做 | — | P2：Computer Use |

**实机失败的根因（来自你的截图和日志，不是模型能力问题）：** 两句话都没有进入工具模式，只是普通聊天，模型自然回答“无法访问”。目前是否给工具，由一份关键词/动词正则（`wants_desktop_action`）决定。放宽关键词治标不治本，需要在 3.1 里去掉这个开关。

## 3. 横向基础（所有场景依赖，先做）

### 3.1 去掉触发开关：通用助手每次发送都走工具路径

这是本计划的第一个决策。此前我建议不要在没有确认的情况下改发送与准入流程，正则开关就是绕开它的临时办法，实机证明它是主要故障点。

目标行为：通用助手的每条消息都走工具路径，由模型决定调用或不调用；模型不支持工具或检查失败时，原样退回普通聊天。

动手前要先查清的事实（不假设）：
- 现有的新鲜能力检查在高负载下耗时多少。如果很快就保持现有安全规则；如果慢，再设计缓存。
- `general_assistant` 默认没有 `profile_id`，所以工具路径与普通聊天的参数差异可能很小；要列出所有分歧点逐一处理：参数来源（`exact_options`）、模型预热步骤、图片与视觉处理、流式界面、重新生成（`_start_regeneration` 读取 `self._task_authorization`）、停止。
- 通用助手的系统提示仍写着“本地文件使用 bash”，这是普通聊天里模型建议用 `ls`/`find` 的原因，统一时一并改掉。
- 要保留的约束：工具授权不保存，不改变“工具”按钮对 Bash/搜索的含义。

### 3.2 让风险等级真正生效

`ToolRisk` 目前只是记录，没有任何代码读取它；确认机制只存在于 Bash 命令。任何修改、删除、移动类工具之前，必须先有通用确认：
- 对 `destructive` 工具，运行前在工具卡片显示预览（精确参数和指纹），用户确认后才执行；`reversible` 自动执行并给出撤销线索；`read` 自动执行。
- 复用现有 `command_confirmation` 的指纹与一次性批准思路，不另写弹窗。

### 3.3 场景评测集

用上面 8 个场景建一套评测：合成工具结果，每题重复 N 次，在 9B 和 27B 上分别跑，评分工具选择与参数。可复用 `llm/harness_probe.py` 的驱动方式。没有它就分不清“复杂就不行”是模型能力还是我们的问题，也无法判断工具数量增加后是否变差。

### 3.4 以打包签名版验收，而不是终端里的 `aide`

终端启动继承了终端的权限，打包版是另一个身份。已知问题（需验证）：
- `aide.spec` 里 `NSAppleEventsUsageDescription` 仍写“读取选中文字和模拟快捷键”，要改成覆盖备忘录、提醒事项、System Events。
- `build.sh` 使用 Hardened Runtime，而 `entitlements.plist` 里没有 `com.apple.security.automation.apple-events`；需确认控制其他应用是否因此失败。
- 下载、文档、桌面目录的 Spotlight 结果是否受应用隐私权限过滤。

### 3.5 上下文里要带上“刚才做了什么”

目前只有用户与助手的消息进入后续上下文，工具结果不进入，所以“刚才那条”无法指代。方案：创建类工具返回条目标识，并在会话里记录“本会话创建/打开过的对象”，随下一轮上下文提供给模型。

## 4. 场景工作流与完成标准

### 4.1 Find（S1）
- 时间过滤（修改时间、最后使用时间）、最近使用排序、可配置搜索根目录。
- 整句查询的分词与降级重试，让“产品方案文档”也能找到“产品方案”。
- 内容匹配：只返回命中的文件，不把内容交给模型。
- 完成标准：S1 在真实机器上返回正确候选，并按时间与相关度排序。

### 4.2 Open（S2）
- `open_path` 增加“用指定应用打开”；识别项目目录（含 `.git`、常见工程文件）与最近使用的项目。
- 完成标准：S2 能在选定的开发工具里打开项目；有多个匹配时让用户选一次。

### 4.3 备忘录与提醒事项（S3、F1、F2）
- 读取：按标题列出/搜索笔记（先不返回正文）；提醒事项同理。
- 修改：只追加，不覆盖。已有资料表明编辑已有笔记可能丢附件、链接、清单，所以必须先通过 3.2 的确认并附预览。
- 删除/完成：删除走确认；提醒事项优先用“标记完成”。
- 创建类工具返回标识（配合 3.5）；提醒事项支持到期时间（探测中模型把“明天下午”写进了标题）。
- 完成标准：F1 能给出数量；F2 能在确认后处理“刚才那条”。

### 4.4 文件整理（S4）
- 两步：`plan_organize` 只返回计划，`apply_plan(plan_id)` 在确认后执行；删除一律移到废纸篓，并保留撤销记录。
- 完成标准：S4 在测试目录上预览→确认→执行→撤销全链路通过。

### 4.5 窗口（S5）
- 在真实桌面验证：授权辅助功能、多屏、全屏应用、没有窗口的应用。
- 完成标准：真实桌面上两个应用并排，失败时给出可执行的提示。

## 5. 体验

- 工具状态：把“工具：关闭”改成能表达“本机工具：自动，Bash/搜索：关闭”；设置里加本机工具总开关和搜索范围。
- 权限页：列出辅助功能、自动化、完全磁盘访问的当前状态，并提供跳转系统设置的入口。
- 结果呈现：文件、应用、窗口以可点击的结果卡片出现在对话里，而不只是文字。
- 候选列表：已有，待实机反馈位置与大小。

## 6. 后续（本轮不做）

- P2：Computer Use 以独立进程 MCP 接入。先做小型试验：测量 9B 对很长的界面状态输出的调用成功率，依赖 3.3。
- P3：跨应用多步骤 Agent。
- 明确不做：插件商店、重写整个 UI、让大模型替代可直接调用的系统接口。

## 7. 待处理的缺陷

- 日志里 `QTextCursor::setPosition: Position out of range` 来源不明；用不含这批改动的提交（`edce7b9` 之前）运行来确认是否由本次改动引入。

## 8. 建议顺序

1. 3.1 与 3.3 并行：先建评测集得到基线，再统一工具路径并对比。
2. 3.2 通用确认，3.5 对话上下文，3.4 打包验收（这三项是 4.x 的前提）。
3. 4.3 备忘录读取/追加/确认 → 4.1 Find → 4.2 Open → 4.5 窗口实机验证。
4. 4.4 文件整理。
5. 第 5 节体验；第 6 节的 P2 试验放最后。

## 9. 需要你决定

1. 通用助手每次发送都走工具路径（去掉触发开关）？我的建议：是。
2. 除通用助手外，哪些角色默认带本机工具？这需要给角色加一个开关；翻译、润色类建议默认关。
3. 备忘录能改到什么程度：只读与追加，还是包含删除（必须确认）？
4. 文件搜索范围：当前是文档、桌面、下载；是否扩到整个用户目录或可配置？
