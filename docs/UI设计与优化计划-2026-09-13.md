# UI 设计与优化计划

更新日期：2026-09-13。本计划面向 400–520px 宽的 macOS 常驻桌面助手，目标是让用户在不阅读说明的情况下理解“对话、捕获、快捷动作”三条主路径。

## 问题判断

1. 原工具栏在一行内同时展示 Agent、模型、图片能力、配置、新对话、历史、导出和设置；窗口较窄时信息被截断，操作也没有主次。
2. 空对话只有大片空白，新用户无法从界面得知全局选中和截图快捷键。
3. 服务状态点放在输入栏末尾，容易被理解为发送状态；输入区的边界和层级也偏重。
4. 快捷动作面板的标题、模式选择、键盘说明和收起按钮拥挤在一行，在最小宽度下会裁切文字。

## 设计原则

- 顶部只保留当前任务必需信息，高频操作可直接点击，低频操作收入更多菜单。
- 把宠物形象用于首屏引导和状态表达，不在消息内容区反复堆叠装饰。
- 输入区始终是最明确的主操作；附件、动作和连接状态都作为辅助信息。
- 所有状态同时使用文字、颜色或提示，不只依赖颜色。
- 以 400px 最小宽度和浅色/深色两套主题作为每次 UI 改动的验收基线。

## 开发分期

### UI-1：信息层级与密度（本轮完成）

- 标题栏展示圆角蓝色猫头鹰图标、产品名、当前 Agent 和服务状态；“新对话”使用标题栏原有空间。
- 第二行专注 Agent、模型、图片能力和模型配置；历史、导出、Agent 管理收入“更多”菜单。
- 服务状态点移出输入栏，模型和 Agent 选择器在最小宽度下仍可用。
- 消息气泡按窗口宽度自适应，输入区改为独立圆角容器。

### UI-2：首次使用与快捷动作（本轮完成）

- 空对话展示桌面猫头鹰、一句主引导和 `⌘⌃L` / `⌘⌃S` / `⚡` 三个入口；出现首条消息后自动隐藏，清空对话后恢复。
- 快捷动作改为“标题 + 对话模式”、“材料状态 + 键盘提示”、“动作按钮”三层结构，保留连续处理能力。

### UI-3：可用性完善（下一阶段）

1. 用真实长模型名、长 Agent 名、中英文长消息和 1–4 张图片建立固定 UI 截图样本。
2. 为更多菜单、模型能力、连接状态和图片操作补齐键盘焦点顺序与可读提示。
3. 检查 100%、125%、150% 缩放与 macOS 浅色/深色即时切换，修复文字截断和对比度问题。
4. 根据一轮真实固定任务使用记录，决定更多菜单内的操作顺序，不凭假设增加新按钮。

### UI-4：宠物与任务状态（基础动作与互动循环已完成）

- 动画必须表达任务含义：读取时侧倾，生成时浮动并点亮电脑，成功时短暂弹跳，失败时轻微摇头。任务状态的动作保持稳定，不被悬停效果覆盖。
- 空闲状态以稳定待机为主，只在较长间隔中播放眨眼这一种微动作。角色保持固定水平位置，不左右晃动；各段之间有安静的呼吸间隔，不自动说话或弹出内容。
- 鼠标停在空闲宠物上时播放一轮短回应：抬头、专注侧倾、轻微挥翅和开心表情，随后停在稳定姿态；移开时立即回到安静待机。眼神、翅膀和表情使用五帧透明精灵图，位移、旋转和缩放只做很小的补充。
- 默认中号容器收窄为 104×110（约比原 116×122 小 10%），降低桌面常驻存在感；小号和大号仍可在设置中选择。
- 减少动画模式禁用所有位移、旋转、缩放和闪光，状态徽标仍保留，保证信息不因关闭动画而丢失。
- 宠物的操作层级为：单击打开对话，拖动调整位置，右键可“截图到对话”或执行最近文字动作。忙碌时相关动作禁用，避免并发任务。
- 下一步只验证“快捷翻译”、“截图识字”、“普通对话”三类任务的返回路径和主观打扰度。若真实使用仍需要更细的表情或翅膀动作，再制作独立多帧角色素材。

## 验收标准

- 400px 宽下所有可见控件都在窗口内，没有重叠和水平滚动。
- 新对话、Agent/模型切换、历史、导出、Agent 管理和快捷动作信号保持原有行为。
- 空对话和有消息对话可正确切换；清空后回到首屏引导。
- 深色、浅色主题下的产品名、气泡、模型状态和输入框都可读。
- 稳定签名的 `.app` 构建和冒烟通过，UI 改动不影响已授予的 macOS 权限身份。
