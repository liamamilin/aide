# F02.1 本地 OCR 技术验证

日期：2026-09-13。环境：macOS 26.6.2 arm64、Python 3.10.13、PyObjC 12.2.2、Apple Vision revision 3。样本全部由本地脚本合成，未读取用户截图或剪贴板。

## 结论

Apple Vision 适合作为 F02 MVP 的默认引擎。它在设备上执行，可返回文字候选、置信度和归一化区域，不需要再捆绑 Tesseract 模型或启动视觉大模型。[Apple 文字识别说明](https://developer.apple.com/documentation/vision/recognizing-text-in-images?changes=lat_2_6_8_8_1&language=objc)

当前 arm64 候选包的 MVP 支持下限建议为 macOS 11；这与 Apple Silicon 产物边界一致。更旧系统和 x86_64 需在有对应硬件的环境重新构建和冒烟，不根据 API 声明直接承诺。

## 依赖与冻结

- `pyobjc-framework-Vision>=12.2.2,<13.0.0` 已显式加入 macOS 依赖。Vision 在 PyObjC 中是独立框架包，不再依赖 `pynput` 的间接安装。[PyObjC Vision 包](https://pypi.org/project/pyobjc-framework-Vision/)
- PyInstaller 显式收集 `Vision` 和其 `CoreML` 桥接；发布预检将两者视为必需模块。
- 包内可执行文件新增 `--ocr-runtime` 自检，隔离冒烟会验证引擎名称和运行时语言列表。
- `1.5.0` ad-hoc 候选 `.app` 完成重建、深度签名验证、schema 3 新库冒烟和 schema 0 升级冒烟。粗粒度体积由约 92MB 增至 93MB。

## 运行时能力

Vision revision 3 在本机返回 30 个准确识别语言，其中包括 `en-US`、`zh-Hans`、`zh-Hant`、粤语、日语和韩语。实际产品只能从该运行时列表选择，不硬编码假定所有系统都支持同样语言。Apple 也明确说明语言顺序会影响识别优先级，并提供运行时支持语言查询。[recognitionLanguages](https://developer.apple.com/documentation/vision/vnrecognizetextrequest/recognitionlanguages?changes=_1) [supportedRecognitionLanguages](https://developer.apple.com/documentation/vision/vnrecognizetextrequest/supportedrecognitionlanguages%28for%3Arevision%3A%29)

在命令执行沙箱中，Vision 会因无法创建 `CVPixelBuffer` 而失败；同一脚本在应用实际运行权限下成功。自动化和候选包验收需保留这个运行环境条件。

## 后续实施状态

F02.2 已在 `9b73b02` 完成：`OCRService` 返回原始文本块、归一化位置、置信度、语言和耗时；`OCRWorker` 在后台执行；`AsyncOCRService` 以任务 ID 只转发当前结果，替换图片或取消后到达的旧结果会被丢弃。基准脚本已改为直接调用该服务，真实 Vision 复测保持中文/英文 CER 0%、混排代码 10.53%、空白图为空。

下一步 F02.3 在图片预览加入“提取文字”入口与可编辑结果，并接入处理中、空白、失败和取消反馈。Vision 原始文本和坐标仍需保留；行序、缩进和全角符号修正放在 F02.4，不在 OCR 原文中静默重写。质量集继续扩充到 50 张，单独统计中文、英文、混排代码和低质量图片。
