# Aide 个人电脑入口设计（草案）

日期：2026-10-26。状态：设计草案，尚未实现。调研依据见文末。

## 目标

Aide 是 macOS 的个人智能操作入口：用户表达意图，Aide 发现本机资源，调用系统与应用能力，执行操作并返回结果。

能力分四档，按顺序交付：Find（找）→ Open（打开）→ Operate（操控）→ Automate（跨应用多步骤）。能直接调用系统接口的事不让模型去模拟鼠标；只有没有接口时才使用界面识别。

## 核心原则

1. **所有 Agent 共用同一套底层**：工具注册表、运行引擎、确认、审计、能力检查。Agent 只是配置（角色提示词 + 模型 profile + 工具选择），不存在“能力更全的特殊 Agent”。通用助手只是默认配置最全的普通 Agent。
2. **风险等级归工具，不归 Agent**：同一工具无论由谁调用，确认规则相同；Agent 配置不能降低风险等级。
3. **精确请求走确定性路径，不经过模型**：只有本地解析无结果或表达模糊时才交给 Agent 循环。
4. **入口统一在对话框**：不新增独立窗口。输入框在短查询时显示本地候选，回车直接执行；长句才发送给模型。

## 与现有设计的关系（需要注意）

现有 [Agent 工具通用化](Agent工具通用化后续计划-2026-10-05.md) 已经让 Bash / Parallel / Exa 对所有对话 Agent 开放，并规定：**每个新对话默认关闭工具，切换 Agent 清除授权**。原因是这些工具需要工作区、命令策略和搜索凭据，授权状态是真实的前置条件。

本设计的“默认开启”因此只适用于**新增的 Aide 原生工具**（文件搜索、应用与窗口发现、打开/定位等无需工作区和凭据的工具），不改变 Bash / 搜索现有的显式授权行为。是否进一步放宽，另行决定。

## 工具注册表

现状：`run_types.ToolSpec` 将名称限定为 `{"bash", "web_search"}`，参数校验和分发按名称分支，`run_worker`、`tool_preferences`、`task_admission` 各自知道这两个名字。

目标：每个工具声明
- `name`、JSON schema、`group`（能力分组）；
- `risk`：`read` / `reversible` / `destructive`；
- `execute`。

参数校验、确认、审计按 `risk` 和 schema 处理，不再按名称分支。

### 能力分组

文件与搜索、应用与窗口、备忘录与提醒、终端与网络（现有 Bash / 搜索）、电脑操控（P2）。设置页按分组展示；每次运行只向模型暴露与请求相关的分组，避免本地小模型因工具过多而选错。

### 风险与确认

| 风险 | 例子 | 行为 |
|---|---|---|
| read | 搜索文件、列出窗口 | 自动执行 |
| reversible | 打开 App/文件、新建笔记、调整窗口 | 自动执行，结果中说明如何撤销 |
| destructive | 移动/删除文件、发送消息、日历邀请、编辑已有笔记 | 预览后必须确认 |

整理文件类任务拆成两步：`plan_*` 只返回计划，`apply_plan(plan_id)` 经确认后执行。模型不能直接写文件系统。确认机制复用现有 `command_confirmation` / `execution_context`，不再另写弹窗。

## 目录结构

新功能放入独立可测试的包，不扩大 `main.py`（约 2900 行）、`chat_dialog.py`（约 2400 行）、`float_button.py`（约 1300 行）：

- `desktop/`：`search`（`mdfind` / `NSMetadataQuery`）、`apps`、`opener`（`NSWorkspace`）、`windows`。同一批函数既供对话框本地候选直接调用，也包装成 `ToolSpec` 供 Agent 使用。
- `integrations/`：Notes、Reminders、Calendar 等；参考开源实现，按需重写，不引入整套 MCP。
- `computer_use/`：P2，以独立进程 MCP 接入，先评估开源实现。

`ChatController` 只增加创建与接线的少量入口代码。仅在出现真实重复时再拆分旧的大文件。

## 对话框入口

- 输入框空闲短暂时间后，对短查询（应用名、文件名）显示本地候选；上下键选择，回车执行。
- 较长或含动词的输入，回车发送给 Agent。判断规则要简单可预期，并提供快捷键强制走另一条路径。
- 选中文字的 `⌘⌃L` 仍显示快捷动作，另增一项“让 Aide 处理”进入通用助手。
- 新工具分组首次出现时，在对话框提示一次，说明新增能力和确认规则。

## 分阶段交付

| 阶段 | 内容 | 验收 |
|---|---|---|
| P0 | 工具注册表重构（行为不变）；`desktop/` 搜索与打开；对话框本地候选 | 找文档、开项目、开 App 三个场景不调用模型即可完成 |
| P1 | 窗口操作；Notes / Reminders 创建类工具 | 创建笔记、调整窗口，危险操作均需确认 |
| P2 | Computer Use（独立进程 MCP） | 先验证本地模型对其长返回的调用稳定性 |
| P3 | 多步骤跨应用 Agent | 另行设计 |

## 待决问题

- 文件搜索默认范围：用户目录下的文档/桌面/下载/项目目录加白名单，还是全盘。倾向前者。
- 本地候选与发送的判断规则细节。
- Computer Use 选型与最低系统版本（候选项目要求 macOS 14+）。
- 新原生工具默认开启与现有“新对话默认关闭工具”的衔接方式。

## 调研摘要

- Computer Use：iFurySt/open-computer-use（MIT，约 2.7k 星，CLI + MCP）、opensymph/open-computer-use（MIT，15 星，两者同名不同项目）、wende/macbeth（MIT，Accessibility 优先，信息不足回退截图 + 本地 OCR）。均以 MCP/CLI 形式提供，无可嵌入的 Python 库；均需辅助功能与屏幕录制权限；自绘界面支持有限。
- Apple 应用集成：54yyyu/pyapple-mcp（MIT，Python，Notes 用 AppleScript，Reminders/Calendar 用 EventKit，带 read/write/draft/send 分级）、jonathanrreed/apple-mcps（MIT，每个 App 一个服务，默认只读）。pyapple 的作者发现编辑已有笔记会丢失附件/链接/清单，因此拒绝这类编辑；日历添加受邀人会立即发出邀请。
- 启动器：未找到开源、macOS、带自然语言 Agent 的现成项目；RustCast、SOL 等只是启动器，未核实其搜索实现。
