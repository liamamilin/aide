# 对话清理崩溃修复与桌面验收

## 真实操作发现

2026-10-07 按既定发布前计划进行桌面验收，在已授权的当前 App 中新建对话后触发截图快捷键，进程崩溃。系统报告为 EXC_BAD_ACCESS / SIGBUS；Python 故障栈指向 `ChatDialog.eventFilter` 的鼠标 Leave 分支，原生栈为 `qtcore_do_find_children` → `dispatchEnterLeave` → `QWidget` 析构。截图工作线程同时处于区域截图等待中，不能据此把原因归为截图权限。

旧实现给用户和助手消息包装控件都安装了对话窗口事件过滤器。在 Enter/Leave 中递归 `findChildren` 寻找编辑按钮；新建对话用 `deleteLater` 清理旧消息，Cocoa 在子控件析构时仍可能产生合成鼠标离开事件，从而遍历正在销毁的 QObject 树。这条实际崩溃路径未被此前的快捷键、唤醒隔离验收覆盖。

只记录故障位置和测试结果，不收录用户历史消息、截图内容或密钥。系统故障报告留在本机 DiagnosticReports，未复制进仓库。

## 修复

- 用户消息包装控件独立处理 Enter/Leave，直接持有编辑按钮引用，不再递归搜索 QObject 子树。
- 新建对话在隐藏/延迟删除之前先撤销按钮引用；直接延迟删除也执行同样清理。按钮提前销毁时清理引用并检查 SIP 生命周期。
- 助手消息不安装多余的鼠标事件过滤器。对话窗口过滤器仅保留滚动和输入相关事件。
- 增加回归：悬停不遍历子树、清空后晚到鼠标事件、按钮提前销毁、直接延迟删除。
- 增加 `conversation_lifecycle` 原生隔离验收：20 轮消息创建、悬停、清空、实际处理 DeferredDelete、重新输入。无模型、搜索、凭据或用户剪贴板访问。

- 源码/冻结原生 Cocoa 各执行 20 轮生命周期验收，通过时间分别 0.787 / 0.792 秒。最新包的选区与唤醒恢复隔离回归也通过。
- 1.5.0 App 约 867MB，严格深度签名、发布预检、OCR/英文语音/Bash/Fluent/审计/任务入口与 schema 0 升级冒烟通过。55 个相关冻结模块与源码一致，20 份相关文档链接有效。
- 凭据助手 CDHash、字节 SHA256 保持不变；Parallel / Exa 已授权密钥在新包后台无提示读取均成功。本轮没有模型生成或搜索 HTTP，也没有修改 TCC。
- 真实桌面自动操作重现原触发顺序：打开历史 → 新建对话 → 截图快捷键；应用没有崩溃。截图达到 30 秒截止后正常回收，之后对话重新打开可用，未生成新的 App 崩溃报告。自动化 Esc 未取消系统截图，因此该操作不能记作 Esc 验收通过。
- 用户随后亲自用物理键盘确认：**中文选区 ⌘⌃L 正确，⌘⌃S / Esc 正常**（原答复“两项都正常”）。自动化跨应用快捷键未响应的现象没有在这次用户实测中复现；工具投递方式是否导致差异仍只是推测，不把自动化那次记为通过。
- 桌面自动操作验证窗口“放大到当前屏幕 → 恢复窗口”，控件状态往返正确；保留当前草稿及附件，没有发送或删除用户内容。

首轮全量在 Fluent SVG 图标绘制中发生原生段错误，保留 `/tmp/aide-lifecycle-full-2026-10-07.log`；后续串行全量通过，未复现。此故障位置不同于本轮消息清理崩溃，原因尚未确定，后续体验继续观察，不把首次退出隐藏为成功。沙箱内源码原生窗口启动退出，允许原生窗口环境后通过，记录同样保留。
