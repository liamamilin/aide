# 工具授权与模型跟随修复

更新日期：2026-10-05。当前工具模型跟随顶栏选择，不再限定或自动替换为 9B。

## 使用规则

- 在同一个通用助手对话中启用工具后，后续轮次保留 Bash / 搜索勾选及工作目录、命令策略和供应商。
- 同一对话切换模型时保留这些授权，工具状态立即显示新模型。旧检查、运行及待确认命令取消；旧按钮不能执行命令。下一次发送对新模型重新检查，再使用该模型完成整个工具循环。
- 新建、切换或加载历史对话，以及重启应用，不继承授权。历史目录可以作为配置提示，不能自动授权。切换 Agent 或修改相关服务/工具设置仍需要重新启用。
- 快捷动作不继承工具授权。普通聊天继续使用原有聊天配置；工具任务使用顶栏模型，生成参数跟随设置及角色专用配置，工具次数与活动时长保持独立有界。

截图一直显示 9B 的原因，是旧实现分别在能力检查、请求创建和状态文字中固定了模型。现在三处都取当前选择：授权面板、`/api/show`、实际模型请求、重新执行、图片能力判断及运行记录一致。不会因所选模型不支持工具而偷偷回退 9B。

## 模型检查与执行边界

启用、发送和重新执行时读取本机 Ollama 的 version/tags/show，记录实际模型名称、digest 和服务版本，并检查 completion/tools 声明。模型缺失、响应无效、能力不支持或检查超时，任务停止并保留材料；不调用另一模型，也不提前写入用户消息。

不再把 H0 的 9B digest 和服务版本作为其他模型的准入门槛。能力声明检查不等于完整行为验收；历史 H0 的 9B 行为与预算证据仍单独保留。运行审计中的 `budget_verified` 必须同时匹配既有 9B 身份、参数与思考模式才为 true。当前请求采用六项有效设置，不把能力声明或修改后的参数标成已经通过旧 H0 预算实验。

工具任务现在使用设置中的上下文窗口、输出、温度、Top P、Top K 与重复惩罚；角色专用配置可覆盖思考、温度与输出，不能替换顶栏模型。模型明确声明的上下文上限不足时拒绝，不偷偷调小参数。思考选项按当前模型声明校验；不支持时提示并使用模型默认。界面、发现检查、实际请求、重新执行与审计共享不可变参数快照，详见 [工具模型参数一致性修复](工具模型参数一致性修复-2026-10-05.md)。工具目录仍不是 OS 沙箱。

检查捕获精确的当前模型。切换后旧回调失效，已获取的另一个模型检查结果不能直接用于新模型请求。运行开始后每个模型步骤使用同一不可变请求配置，不在工具循环中途换模型。
