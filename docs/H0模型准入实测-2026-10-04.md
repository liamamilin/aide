# H0 模型准入实测

日期：2026-10-04。结论：**qwen3.5:9b-mlx 在明确联网意图、受控模拟工具和下述参数组合下通过小样本准入，可进入 H1 开发。应用尚未接入工具执行。**

按用户确认，使用本机已有模型，优先 9B，不下载原方案的三个模型。`qwen3.8:27b-mlx` 只完成能力发现，不能沿用 9B 的准入结论。模型准入用于开发选型，与真实命令、搜索、取消、权限及打包验收分开。

## 环境与声明

Ollama 实测版本为 `0.34.3`。请求直接访问本机回环地址，不走代理、不调用云端模型；测试不读取用户文件、不执行模型命令、不调用付费搜索。所有工具结果来自固定内存数据。

|---|---|---|---|---|
| qwen3.5:9b-mlx | `203e30078279db51132b9e026ceb7bb21330e5b1af67ef190671b375c9770404` | completion / vision / thinking / tools | false、true；默认 true | H0.1–H0.5 受限通过 |
| qwen3.8:27b-mlx | `5642e97495e1a088883805981563dcdc4a040c2f53388b7a41d1f24d3622cf7e` | completion / vision / tools / thinking | false、low、medium、xhigh；默认 medium | 仅 H0.1，后续待测 |

## 五阶段结果

| 阶段 | 实测与证据 | 结论 |
|---|---|---|
| H0.1 能力发现 | 版本、模型 digest、精确思考取值 | 两个候选已发现 |
| H0.2 行为验证 | 9B 开/关各三次，使用同一问题和参数，答案均正确；关闭无 thinking，开启有 thinking | 9B 开关生效；任务选择 false |
| H0.3 生成与延迟分布 | 简单、规划、工具请求各五次；总生成量中位数 27、样本 P95/max 108；耗时中位数 0.784 秒、样本 P95/max 3.025 秒 | 仅用于这 15 个短样本，不外推一般任务 |
| H0.4 预算选择 | 三项正常闭环通过；num_predict=1 返回 length；流式单次与重复调用通过；1/4 条各 4 KiB 工具结果通过 | 固定组合可用于初期开发，隐式 shift/truncate 仍未知 |
| H0.5 工具准入 | 明确联网意图版本的十项任务各两次；答案须有实际工具结果证据，失败须先观察到错误再完成备用流程 | 单工具 8/8，多步 8/8，失败恢复 4/4 |

H0.3 的每类只有五次重复，同一 seed 也不保证不同批次生成完全一致，百分位是小样本描述。另两批开关实验中，关闭约 392–404 个生成 token、耗时约 10–13 秒；开启约 1288–2752 个生成 token、耗时约 33–73 秒。开启存在明显额外成本，但没有可靠的 thinking token 专项计数，不能拿 thinking 字符长度代替 token。

在工具结果压力样本中，1 条和 4 条结果的 prompt_eval_count 分别为 649 和 2200，最终回答保留全部验证代码，均有本轮输出和余量空间。这里只证明已测试的 ASCII 内容样本；中文、代码、图片和更长历史必须由 H1 继续测量和控量，不能固定按 bytes/4 换算。

## 保留的失败与对照

首轮与第二轮的完整任务集均为：单工具 75%、多步 100%、失败恢复 50%，不准入。模型将未明确联网的“搜索指南”理解为查本地文件；备用流程有时跳过首次尝试，有时连续重试模拟器不支持的 Bash。第二轮明确工具职责与顺序，仍未消除模糊搜索任务的歧义。

第三次对照只把两项任务改为明确“搜索网页”，四次均正确选择 web_search，超时后按顺序读取本地文件。随后完整复测十项任务各两次，全部通过。评分门槛没有降低：同名重复读取需要两份结果；验证代码必须实际出现在成功工具结果中；失败恢复须先观察到相应错误；计划链须读取计划和版本文件。

因此结论是**明确联网意图的任务可准入**，不宣称模糊“搜索”也已可靠。H1 的提示词和状态反馈须清楚区分本地 Bash 与联网搜索，保留调用轨迹，不因用户说“搜索”就默默提高权限。原失败记录保留，后续改模型、服务、提示词或预算时重新验证。

## 开发用参数组合

```yaml
model: qwen3.5:9b-mlx
think: false
num_ctx: 8192
num_predict: 1024
temperature: 0
max_model_rounds: 8
max_tool_calls: 16
max_search_calls: 6
tool_result_bytes: 4096  # 每项上限，还需总上下文预算
shift: unknown
truncate: unknown
```

这是一组实测任务配置，不改变当前聊天或用户的全局设置。temperature=0 用于当前受控验证；seed=41/42 用于重复任务，对服务是否严格实现确定性不作承诺。

运行中仍需完整调用/结果块的上下文预算、首次 length→limited、迟到事件过滤和取消。H0 实际观测每轮最多一个调用；同轮多调用、混合 ID、任意增量参数协议由 H1 的构造与提供商样本继续验收。流式实测有服务端 ID，保持原始调用顺序，重复读取发生在两个步骤，不能把它称为已验证同轮并行调用。
