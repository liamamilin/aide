# 新功能开发计划

日期：2026-09-13。状态：待验证、待开发。方向依据：[产品方向与路线图](产品方向与新功能路线图-2026-09-13.md)。基础依赖：[D00–D12 开发规划](详细开发规划-2026-09-13.md)。

## 1. 实施规则与总排期

先完成稳定性 M1 和基础体验 M2，再开始新功能。MVP 指能完成用户场景、通过异常/升级测试的最小版本，不等于只做按钮或演示。

| 批次 | 顺序 | 净投入 | 含约 20% 缓冲 | 决策 |
|---|---|---|---|---|
| M3 / v1.6 | F03 → F01 → F13 → F02 | 9–14.5 人日 | 11–18 工作日 | 桌面宠物作为产品形态主线 |
| M4 / v1.7 候选 | F04、F05、F06、F10 | 若全选为 7–11 人日 | 9–14 工作日 | 根据 M3 使用记录选取，可拆版本 |
| M5 / v1.8 候选 | F08；按分发需求选 F07 | 两项全选为 5–9 人日 | 6–11 工作日 | 先验证用户场景 |
| 实验池 | F09、F11、F12 | 各自限时 | 不合并承诺 | 实验通过才估算并批准 MVP 范围 |

基础 M1/M2 加推荐 M3，整体建议按 **19–32 个工作日**安排。此数包含两份计划各自的缓冲，不再次叠加；日历时间取决于维护者每周投入。

每个功能交付时：UI 行为明确、配置/数据向后迁移、失败可恢复、功能可关闭、真实安装包验证、文档同步。涉及新依赖的功能必须提前验证 PyInstaller 打包，不能留到最后一天。

## 2. 共同设计约定

- 请求统一走 D01–D03 的事件与生命周期，不各自实现一套线程、历史保存、取消逻辑。
- Agent 表示角色；Action 表示一次操作；ModelProfile 表示推理设置。三者引用组合，不复制相同的提示词内容。
- 来源材料保存为明确的 ContextItem（类型、来源、显示名称、内容/附件引用、截断范围），用户可看见本次实际提交的材料。
- 新增数据通过版本化迁移；删除会话、收藏、临时文件时统一更新附件引用，避免形成不受管理的文件副本。
- 文档内容、OCR 结果和检索片段是待处理材料，不作为执行指令；第一阶段所有新功能仅生成结果，不执行材料中的命令。
- 工程模块名称以下均为建议。按功能出现时新增，不能为远期功能一次性建立空框架。

## 3. F03：任务模型配置（M3 第一步）

**状态**：已完成代码与自动化验收。schema 2、ModelProfile、Agent 绑定、唯一参数解析器、不可变请求快照、配置管理界面和回退提示均已实现；完整证据见开发进度。

**用户场景**：翻译沿用一个模型与简短输出，代码解释使用另一组参数；切换任务不必反复进入设置。

**依赖/成本**：D01、D04、D09；1.5–2.5 人日。

**MVP 范围**：模型、思考开关、temperature、输出上限四项；其余选项沿用全局。每项允许“继承”。不自动跑模型性能测试，不下载模型。

开发任务：

1. F03.1：新增 ModelProfile 存储与校验，字段包括 id、name、model、options、updated_at；为 Agent 增加可空 profile_id。
2. F03.2：实现唯一配置解析器，优先级为“本次临时覆盖 → 动作配置 → Agent 配置 → 全局默认”；提交时生成不可变快照。
3. F03.3：在角色/动作编辑器中选择配置，并可恢复继承；请求中的参数摘要可查看。
4. F03.4：模型不存在、能力不匹配、配置被删除时提示并回退继承；当前进行中的请求不被配置变更影响。

**验收**：旧用户升级后行为与原全局配置一致；切角色可以稳定复现参数；请求中切配置不改正在生成的请求；删除配置不会损坏 Agent。

**交付物**：拟议 `services/model_profiles.py`、存储迁移、编辑界面、参数解析/升级测试。模型名字由用户已安装列表选择。

## 4. F01：快捷动作面板（M3 第二步）

**状态**：已完成代码和自动化验收。F01.1–F01.5 均已落地；真实 macOS 选取→翻译→复制、富文本剪贴板与中文输入法交互保留为 M3 桌面验收项。

**用户场景**：选中一段话，唤起助手后直接选择“翻译”，无需再写指令；仍可改成自由提问。

**依赖/成本**：D03、D05、F03；2.5–4 人日。

**MVP 范围**：翻译、解释、摘要、改写四个内置动作；至多置顶四个，允许重命名/隐藏和选择 Agent。沿用当前唤起热键，动作面板模式可关闭；第一版不增加四套全局快捷键。

开发任务：

1. F01.1：补完整剪贴板保存/恢复，保留可枚举的原格式而非只写纯文本；根据变化序号识别用户在捕获期间的新复制操作，不能覆盖新内容。无法完整保留的类型要识别并退出捕获，提供手动粘贴路径。
2. F01.2：定义 Action：id、name、agent_id、可空 profile_id、input_types、instruction、pinned_order。捕获内容作为用户材料传入，不能通过字符串替换升级为系统指令。
3. F01.3：选取后进入动作栏，方向键/数字键选择，Enter 执行，Esc 返回自由输入；没有文本时允许手动输入，中文输入法候选状态不误触。
4. F01.4：结果复用现有气泡、复制和追问；执行失败保留原文和动作；动作启动时新建专用会话，若从现有聊天触发则明确选择“在当前对话继续”。
5. F01.5：持久化常用顺序和上次模式，移除或禁用的 Agent 有有效回退；不会修改用户原有自定义提示词。

**验收**：完整完成选取→翻译→复制；无选择、权限不足和中文输入法均可恢复；原剪贴板的文字/图片/富文本测试通过；采集过程中用户的新复制不被旧快照覆盖；与当前流程比较至少减少一次手动操作。

**交付物**：拟议 `services/action_service.py`、`ui/action_panel.py`、捕获改造与状态测试、快捷键说明。

**止损**：先做简单动作栏；若日记显示没有减少操作，就不扩展独立命令面板或复杂模板语言。

## 5. F13：桌面宠物产品形态（M3 新增主线）

**状态**：F13.1–F13.3 已完成代码和自动化验收。原创猫头鹰角色、任务状态、紧凑模式、隐藏窗口结果摘要，以及最近快捷动作均已接入。

**用户场景**：用户在桌面上能随时看到助手是否空闲、正在读取材料或生成结果，点击即回到对话，不需要理解抽象状态灯。

**MVP 边界**：角色只在用户动作或请求状态变化时反馈；不随机对话、不跟随鼠标位置游走（保留原有跨屏切换）、不连续弹出内容。保留紧凑悬浮球和完全隐藏入口。

开发任务：

1. F13.1（已完成）：原创猫头鹰透明宠物素材；116×122 悬浮容器；轻量漂浮、悬停反馈、读取/生成/结果徽标；打包资源校验；设置和右键菜单可切回紧凑模式。
2. F13.2（已完成）：当对话窗隐藏时，用可关闭的短气泡呈现“完成/失败/需要处理”；只显示摘要，点击后打开完整结果，并与系统通知去重。
3. F13.3（已完成）：右键宠物提供最近快捷动作，单击仍打开对话；动作复用当前选区、F01 配置和后台结果气泡，不为每个动作新增全局快捷键。
4. F13.4：增加“减少动画”和尺寸选项，记录闲置 CPU 与多屏/缩放表现；隐藏后所有动画定时器停止。

**验收**：点击、拖动、跨 Spaces、窗口隐藏、重启位置、紧凑回退与状态切换均可恢复；闲置 10 分钟没有持续 CPU 峰值；不因透明区域遮挡明显桌面操作。

## 6. F02：本地截图识字 OCR（M3 后续）

**用户场景**：框选报错或不能复制的段落，先拿到文字，再复制、翻译或解释。

**依赖/成本**：D05、D08、D09；与 F01 复用动作入口。3–5 人日，含 0.5–1 天技术验证。

**MVP 范围**：截图/已附加图片提取中英文文字，可编辑预览，复制或作为文字提问。原图仍可选择走视觉问答。先不承诺表格复原、手写/数学公式识别或扫描 PDF 批处理。

开发任务：

1. F02.1：验证 Apple Vision 的 Python 调用、目标系统版本、所需 PyObjC bridge 与冻结包；测试英文、中文、混排和代码截图。桥接模块显式声明依赖，不假定 pynput 的间接依赖会覆盖 Vision。
2. F02.2：新增 OCRService，输入受管图片，输出文本块、位置、置信信息与语言；后台执行，结果携带任务 ID，关闭/替换图片时不应用旧结果。
3. F02.3：新增“提取文字”入口和编辑预览；空白图、无识别结果、低质量图片给出清晰反馈；语言配置仅使用运行时支持列表。
4. F02.4：按行序合并文本并尽量保留代码缩进；复制使用原始 OCR/用户修订文本。可选“整理格式”另行调用模型，不能冒充 OCR 原文。
5. F02.5：确认使用文字后由现有请求管线发送；用户可选择同时附原图，但不得在“仅提取文字”动作中隐式启动视觉推理。

技术依据：Vision 的文字识别请求可返回文字及区域，实际语言组合与识别效果取决于运行环境，需查询并测试。[Apple 官方说明](https://developer.apple.com/documentation/vision/recognizing-text-in-images?changes=lates_7)

**质量样本**：50 张合成/公开许可截图：中文 20、英文 20、混排代码 10；固定字体、缩放和人工真值，避免使用私人屏幕内容。记录字符错误率 CER（编辑距离/真值字符数）和行序。

**验收目标，尚未测得**：清晰中英文截图分别 CER ≤5%；混排样本 ≤10%，同时单独核验代码符号与缩进。无文本时不编造内容；连续执行/取消 20 次无崩溃；冻结包可在声明支持的系统上运行。若门槛未达，记录失败样本，保持实验状态。

## 7. F04：重新生成与答案版本

**用户场景**：最后一个问题回答不满意，可以重新生成并查看前一个答案，不丢失历史。

**依赖/成本**：D03、D08；2–3 人日。M4 候选。

开发任务：

1. F04.1：限定第一版只重新生成“最后一条用户消息”的答案；历史较早消息编辑继续采用现有回填再发送，不新增任意分支编辑。
2. F04.2：增加 generation 记录，关联 user_message_id、request_id、配置快照、状态、答案和 active 标记；旧助手回复迁为默认版本。
3. F04.3：同一个问题可查看版本、复制和选择有效答案；后续上下文只加入所选版本，不能同时发送多个互斥答案。
4. F04.4：网络失败重试复用原用户消息，取消的新版本不覆盖之前成功版本；有后续追问时禁用切换旧答案，直到以后支持明确分支。

**验收**：重试不重复用户提问；重启可恢复所选答案；失败/取消保留旧答案；从旧库升级前后对话顺序不变。

**扩展条件**：只有用户频繁编辑早期消息时，才设计完整会话分支，另估工作量。

## 8. F05：收藏与片段复用

**用户场景**：收藏一段可用的解释或写法，以后搜索并再次复制。

**依赖/成本**：D08、D10；2–3 人日。M4 候选。

开发任务：

1. F05.1：收藏保存内容快照、标题、创建时间和可空来源消息引用；源会话删除后快照仍可使用，并解除来源关系。
2. F05.2：回复操作栏增加收藏；单独轻量列表支持标题/正文搜索、重命名、删除、复制。
3. F05.3：明确“用作新对话材料”，不会把收藏内容变成隐藏记忆或系统指令。
4. F05.4：MVP 仅收藏文本；图片收藏若增加必须复用附件引用。导出文本 Markdown 可后续加入，不建设笔记目录树或云同步。

**验收**：收藏后重启可查；来源删除不丢失收藏；取消收藏不删除原消息；重复点击收藏幂等。

## 9. F06：临时会话

**用户场景**：某次问题不希望进入应用的历史、输入回溯或收藏索引。

**依赖/成本**：D03、D08；1.5–2.5 人日。M4 候选。

开发任务：

1. F06.1：创建临时会话时明确显示模式；内存消息仓库复用请求接口，不调用正常会话/输入历史写入路径。
2. F06.2：临时图片放会话临时目录，正常结束删除；崩溃后下次启动清理未完成目录，不改动其他会话文件。
3. F06.3：日志不保存正文、OCR 文本或附件内容；运行诊断只留错误类型与匿名任务标记。
4. F06.4：关闭时清空应用持有的数据；若用户要保存为普通会话，提供明确动作并一次性迁移消息/附件。

**验收**：完成临时会话后检查应用数据库、输入历史与受管临时目录，不含对应正文/附件；崩溃恢复清理通过。产品措辞限定为“不保存到本应用历史”，不承诺操作系统缓存、剪贴板或配置的模型服务不存在记录。

## 10. F10：桌面使用偏好

**用户场景**：只用菜单栏、希望启动即常驻，或想自定义文字/截图快捷键。

**依赖/成本**：D05、D07、D11；1.5–2.5 人日。M4 候选。

开发任务：

1. F10.1：设置统一暴露文字、截图快捷键；校验格式、应用内部冲突；注册失败保留旧绑定。
2. F10.2：悬浮按钮、菜单栏、启动打开聊天等偏好持久化；至少保留一个可见/可用入口，避免应用无法唤起。
3. F10.3：验证适合冻结包的登录启动实现，用户开关后再安装对应启动配置；应用移动/升级后的路径检查和关闭清理要配套。
4. F10.4：权限缺失提供对应引导；无法枚举其他 App 全部快捷键时只说明检测范围，不声称能检测所有系统级冲突。

**验收**：开关登录启动可逆；移动应用或注册失败有反馈；重启偏好正确；隐藏浮球后仍能打开对话。

## 11. F08：文件作为本次上下文

**用户场景**：把一份说明文档拖进来，明确选择内容范围后询问，并能回到引用的位置。

**依赖/成本**：D03、D08、D09；3–5 人日。M5 候选。

**MVP**：UTF-8 文本、Markdown、含文字层的 PDF；建议初始最多 3 文件、合计 10MiB。加密/损坏文件、扫描 PDF 给出说明；不隐式 OCR 整本扫描文档。

开发任务：

1. F08.1：用 0.5 天验证文件解析、页码/行号、打包体积；选择依赖前比较维护和安装成本，记录决定。
2. F08.2：后台提取并保留来源定位，用户预览本次选中的页/段；超过上下文预算时要求缩小范围，不静默只取开头。
3. F08.3：构造 ContextItem，包含 document_id、内容哈希、页/行范围、片段编号；正文作为材料传入。
4. F08.4：模型可引用既有片段编号；UI 只接受本次提供的编号并显示原文。编号有效只证明来源存在，不证明答案正确，需样本人工核验。
5. F08.5：文件删除、修改或移动后历史显示“来源不可用/已变化”；保留受管副本时计入数据清理界面。

**验收**：短文本、Markdown、正常 PDF、多页截取、过大文件、乱码、扫描/加密 PDF 均有确定结果；20 个固定问答能查看对应来源；引用不存在的片段不能呈现为已验证来源。

**上下文策略**：按所选模型容量留出系统提示和输出空间，保留完整用户/助手轮次；token 数无可靠算法时标注估算。先做显式范围选择，再考虑自动摘要或检索。

## 12. F07：首次使用与模型下载向导

**用户场景**：新安装后知道服务是否在线、有没有模型、下一步该做什么。

**依赖/成本**：D04、D07、D09；2–4 人日。对外分发需求出现时安排，可先于 F08。

开发任务：

1. F07.1：复用现有欢迎/检测，组成可重进的状态页：服务、模型、必要权限、示例首问；不重做已完成的检测逻辑。
2. F07.2：模型候选由显式维护的元数据或用户输入给出，显示用途/体积已知值；未知大小如实标注，不能凭参数规模精确推断内存。
3. F07.3：用户选择并确认下载后调用 pull，显示状态、已知进度和错误；提供重试。
4. F07.4：验证停止下载和恢复语义；关闭进度窗口不应谎称服务端下载已经取消。下载成功后刷新模型能力，再进入示例提问。

技术依据：Ollama 的模型拉取接口提供流式进度；取消及断点行为需要针对支持版本实测。[Ollama 官方说明](https://docs.ollama.com/api/pull)

**验收**：服务未装/未启动、在线无模型、下载失败/空间不足、已有模型、权限拒绝均能返回可继续的状态；用户未确认时不启动模型下载。

## 13. F09：指定文件夹知识问答实验

**进入条件**：F08 已完成，而且使用记录出现跨多个文档重复查找的问题。成本：先 2 天实验，通过后另需 6–10 天 MVP。

**两天实验**：第一天建立 50–100 份合成/公开许可文本资料、切片和关键词检索基线；第二天比较本地 embedding 检索，做引用展示原型。先用简单可替换的索引存储，不先引入独立向量数据库服务。

本地语义索引可调用 Ollama embedding 接口。索引必须记录模型与向量维度，换模型后重建，不能混用向量空间。[Ollama 官方说明](https://docs.ollama.com/api/embed)

**继续标准，属于实验目标**：30 个可回答问题的相关片段 Recall@5 ≥80%；10 个无答案问题至少 8 个提示材料不足；抽查引用与答案支持关系 ≥90%。记录检索耗时、索引时间和磁盘占用，对比关键词基线；不满足时先改善检索，不增加 agent 编排。

**通过后的 MVP 任务**：

- F09.1：用户选择单个目录，预览收录范围；默认忽略隐藏/系统文件与符号链接越界，不做全盘扫描。
- F09.2：建立文档哈希、切片、索引任务和进度；手动刷新，支持取消，已删除文件移除索引；后续才考虑文件监听。
- F09.3：查询→检索→展示材料→生成带引用答案，材料不足可直接展示检索结果。
- F09.4：可清除整个知识库和重建；模式/模型变化使旧索引失效；内容被视为材料，不执行其中指令。
- F09.5：在目标 Mac 上声明并验证首版规模上限，不承诺海量文件和跨目录企业搜索。

## 14. F11：按住说话输入实验

**进入条件/成本**：维护者确认打字是实际瓶颈；先 1–2 天验证，之后另估 4–7 天 MVP。

验证本地转写候选的中英混说质量、最低系统、资源消耗、打包、离线行为。拟议 MVP 只允许主动按键录音，松开转写，编辑后发送；有明确录音状态和取消键。保存音频默认关闭，禁止后台持续监听。

继续目标：30 段固定短音频至少 90% 得到可人工轻改后使用的文本；无网络时可运行；录音权限拒绝和设备切换不崩溃。此处的 90% 是人工可用率，不冒充自动转写准确率。

后续任务：F11.1 录音控制与权限；F11.2 本地转写适配器；F11.3 输入框回填和取消；F11.4 音频清理、设备变更和冻结包测试。未达标则停止，不自动退到云服务。

## 15. F12：受控写回原应用实验

**进入条件/成本**：F01 使用证明最后一步手动粘贴确有负担；先 2–3 天只针对文本编辑器验证，通过后另需 5–8 天 MVP。

流程：捕获时记录来源 App 和选区快照 → 生成 → 用户查看结果并点击“替换” → 校验前台目标与选区仍匹配 → 单次写入。目标发生变化时回退复制，不猜测当前输入位置。

后续任务：F12.1 目标身份/选区校验；F12.2 受支持 App 白名单式适配；F12.3 写回反馈与可用的撤销策略；F12.4 用户切窗、选区变化、权限撤销、剪贴板变化等异常测试。

继续标准：在明确支持的 App、固定用例中错误目标写入为 0；每次结果都可见，撤销路径经过实际验证。不承诺跨应用通用撤销，不扩展到自动发送邮件、执行终端命令或后台多步操作。
