# 产品方向与新功能路线图

日期：2026-09-13。状态：产品建议，尚未经过用户访谈或使用数据验证。开发拆解见[新功能开发计划](新功能开发计划-2026-09-13.md)，基础工程见[详细开发规划](详细开发规划-2026-09-13.md)。

## 1. 建议的产品定位

**一个以轻量桌面宠物形态常驻的 macOS 本地助手：围绕用户当前选中的文字、截图或主动附加的材料，快速完成理解、改写和整理。**

优先服务三个具体场景：

| 场景 | 用户想完成的事 | 现有基础 | 仍有摩擦 |
|---|---|---|---|
| 阅读与学习 | 翻译段落、解释术语、提炼结论 | 全局选取、翻译/摘要 Agent | 仍要切角色、输入重复指令；截图文字依赖视觉模型 |
| 开发与排错 | 解释错误、理解代码或界面截图 | 代码 Agent、图片输入、Markdown | 模型/思考参数要反复改；异常输出与上下文边界不清 |
| 写作与沟通 | 改写句子、整理表达、复用结果 | 润色 Agent、复制、历史 | 修改版本不可比较；结果缺乏轻量收藏和复用 |

这些用户需求是由现有功能与产品形态推导的假设，不是市场份额、竞品缺口或已验证需求。

## 2. 三条方向及取舍

| 方向 | 价值假设 | 与项目的适配 | 成本/不确定性 | 建议 |
|---|---|---|---|---|
| A. 桌面上下文处理 | 减少复制到别处、写指令、切模型的步骤 | 选取、截图、悬浮与 Agent 都可复用 | 需要稳定捕获和低延迟交互 | 近期主线 |
| B. 个人结果整理 | 好答案、常用写法和自定义动作可以再次使用 | 已有 SQLite、历史和自定义 Agent | 容易扩展成复杂笔记系统 | 中期只做轻量收藏与版本 |
| C. 本地资料问答 | 对选定文件或文件夹提问且能找到来源 | 本地模型与持久化可复用 | 解析、检索、引用质量、索引维护均是新能力 | 先文件附件，再做限时实验 |

语音、跨应用写回、任务自动化作为探索池。当前代码中的 Agent 是角色提示词，不是可执行工具的自主代理；新增自动化意味着新的执行与恢复体系，应独立立项。

## 3. 产品原则

1. **用户主动提供上下文。** 默认只处理选中文字、框选截图、主动添加的文件；不连续录屏、不全盘索引、不常驻记录剪贴板。
2. **结果能继续使用。** 优先做好复制、继续追问、查看来源、比较版本；自动写入其他 App 要有独立明确的动作。
3. **模型选择可理解。** 显示文本/图片等能力，按任务记住偏好；能力未知时如实标注，避免静默切换或下载大模型。
4. **先保证一条路径顺畅。** 以一次翻译、一次解释、一次改写的完整流程验收，按钮数量不代表价值。
5. **本地优先需要可核验。** 配置中的服务地址可以改变，Ollama 本身也可能连接云能力；回环地址并不能证明模型在本机执行。[Ollama 官方说明](https://docs.ollama.com/cloud) 产品应展示所配置的推理位置，并单独说明更新检查和用户发起的模型下载。严格离线模式需要验证服务端与所选模型行为，不能只检查 URL 就承诺不外传。

6. **宠物形态服务于状态和行动。** 角色反馈要解释正在读取、生成、完成或失败，并帮助用户进入常用动作；不做无意义弹窗、随机打扰或高频动画。

## 4. 新功能候选池

成本是单人完成 MVP 的净开发及验证人日，前提是依赖已完成；不包括排期缓冲。高、中、低是维护者视角的相对判断，没有使用虚构评分或用户数量。

| ID | 功能 | 典型使用流程 | 价值/适配判断 | 成本 | 建议阶段 |
|---|---|---|---|---|---|
| F01 | 快捷动作面板 | 选中文字 → 选“翻译/解释/改写” → 结果 | 高频、直接复用入口，优先验证 | 2.5–4 天 | v1.6 主线 |
| F02 | 本地截图识字 OCR | 框选 → 提取文字 → 复制或提问 | 降低纯文字截图对视觉模型的依赖 | 3–5 天 | v1.6 主线 |
| F03 | 任务模型配置 | 翻译和排错分别记住模型、思考偏好 | 减少重复配置，易验证 | 1.5–2.5 天 | v1.6 主线 |
| F04 | 重新生成与答案版本 | 重试同一提问 → 比较版本 → 选择继续 | 提升长对话可控性 | 2–3 天 | v1.7 候选 |
| F05 | 收藏与片段复用 | 收藏答案 → 搜索 → 复制/带入新对话 | 让历史变得可再次使用 | 2–3 天 | v1.7 候选 |
| F06 | 临时会话 | 开启临时 → 提问 → 关闭后清理 | 满足不留本地历史的明确需求 | 1.5–2.5 天 | v1.7 候选 |
| F07 | 首次使用与模型下载向导 | 检测状态 → 用户选择模型 → 下载进度 → 首问 | 适合准备对外分发时 | 2–4 天 | 按新用户反馈决定 |
| F08 | 文件作为本次上下文 | 拖入文本/Markdown/文字 PDF → 选择范围 → 带来源提问 | 先验证资料问答需求，范围可控 | 3–5 天 | v1.8 候选 |
| F09 | 指定文件夹知识问答 | 选择目录 → 索引 → 搜索/提问 → 查看引用 | 潜在价值高，工程与质量风险也高 | 实验 2 天；通过后另需 6–10 天 | 后续实验 |
| F10 | 桌面使用偏好 | 开机启动、显示入口、统一快捷键设置 | 配置一次后长期受益 | 1.5–2.5 天 | v1.7 候选 |
| F11 | 按住说话输入 | 按键录音 → 本地转写 → 编辑后发送 | 输入便利性取决于实际使用 | 实验 1–2 天；通过后另需 4–7 天 | 探索池 |
| F12 | 受控写回原应用 | 预览改写 → 点击替换 → 验证目标 → 写回 | 可减少最后一次粘贴，但误写代价高 | 实验 2–3 天；通过后另需 5–8 天 | 探索池 |
| F13 | 桌面宠物产品形态 | 常驻宠物 → 看见状态 → 点击对话/动作 | 强化可感知入口与状态反馈，需控制打扰和资源占用 | 2–3 天 | v1.6 产品形态主线 |

## 5. 第一组新功能为什么这样选

### F01：把重复提示变成明确动作

已有 Agent 决定“以什么角色回答”，快捷动作决定“这一次做什么”。建议继续复用 Agent 的提示词和配置，在动作里只保存角色引用、必要变量及结果展示方式，避免生成两套内容相同的提示词管理系统。

MVP 保持现有自由提问入口，附加至多四个常用动作：翻译、解释、摘要、改写。用户可以在打开对话后选择动作；启用快捷面板模式后也可在选取后直接选动作。第一版不为每个动作注册全局热键。

判断价值：同一组固定任务，与当前流程相比是否减少操作步骤和反复输入指令，同时不提高误触率。

### F02：区分“提取文字”和“理解画面”

截图中的报错、段落通常需要先得到可复制文本；图表、照片和视觉关系仍走现有视觉模型。界面提供“提取文字”和“向模型提问”，不把两条路径混为自动判断。

Apple Vision 提供设备端文字识别能力，可返回识别文字及其位置。F02.1 已完成 Python 桥接、冻结包和合成样本验证：中英文 CER 为 0%，混排代码为 10.53%，因此选定 Vision 作为 MVP 引擎；F02.2 已完成异步服务、任务取消和过期结果保护。代码符号和缩进仍为专项质量项。[Apple 官方说明](https://developer.apple.com/documentation/vision/recognizing-text-in-images?changes=lat_2_6_8_8_1&language=objc) [完整验证记录](OCR技术验证-2026-09-13.md)

MVP 先输出可编辑纯文本，保留基本行序；表格结构、数学公式和复杂版式重建不作为第一版承诺。

### F03：让模型配置跟随任务

给每个 Agent 或动作选择“沿用全局”或指定配置。例如翻译偏好较短输出，复杂解释可启用思考；这是产品预设，不预先指定必须下载某个模型。

本次请求使用参数快照，下一次才采用新设置。模型被删除或服务离线时显示问题并提供选择，避免静默落到其他模型改变结果质量。

### F13：让悬浮入口成为可理解的桌面伙伴

桌面宠物不只是替换图标。第一阶段已用原创角色表达空闲、读取选区/截图、生成、完成和失败，同时保留拖动、跨 Spaces、右键菜单和 44×44 紧凑回退。第二阶段已加入只在完整窗口隐藏时出现的可关闭结果摘要，并与系统通知去重。

第三阶段已从宠物右键菜单提供最近动作，复用当前选区直接后台执行。第四阶段已加入减少动画和小/中/大尺寸，隐藏后停止宠物计时器。后续只补充与任务有关的权限或服务反馈，闲置时不主动说话。

## 6. 分阶段路线图

| 阶段 | 主目标 | 范围 | 退出条件 |
|---|---|---|---|
| M1 / v1.4.1 | 可稳定使用 | D00–D07 | 核心状态与桌面/安装包验收通过 |
| M2 / v1.5 | 图片与历史可靠 | D08–D12 | 旧数据升级、图片回收、历史与窗口恢复通过 |
| M3 / v1.6 | 少写指令，少切配置，让助手状态可感知 | F03 → F01 → F13 → F02 | 固定场景测试通过，桌面宠物无明显打扰，并完成至少一轮实际使用记录 |
| M4 / v1.7 候选 | 结果可比较、可复用 | F04、F05、F06、F10 中按反馈选择 | 只交付被使用验证支持的功能 |
| M5 / v1.8 候选 | 明确来源的材料问答 | F08；对外分发时考虑 F07 | 用户确有反复附加材料/安装困难的需求 |
| 实验池 | 测量可行性 | F09、F11、F12 | 达到各自继续/停止条件后再安排 MVP |

M3 净投入约 7–11.5 人日，含 20% 缓冲按 9–14 个工作日；M4 若四项全选为 7–11 人日，含缓冲按 9–14 天。M4 及以后不承诺日历发布日期，也不默认全部实施。

## 7. 如何验证方向

先由维护者建立 20 个不含个人敏感信息的固定任务：翻译 5、解释代码/报错 5、改写/摘要 5、截图提取 5。当前版本记录基线，新版使用同一批任务比较。

| 指标 | 记录方式 | 初步目标或判断 |
|---|---|---|
| 任务完成 | 得到可用结果并复制/继续使用 | 20 个固定任务至少 18 个完成；人工评估可用性 |
| 操作成本 | 唤起到提交所需动作数、重复输入字数 | 快捷动作的中位操作数较当前流程减少至少 1 步 |
| 应用可靠性 | 应用错误、错会话、卡住输入 | 固定任务中不出现错会话或不可恢复状态；模型答案质量另记 |
| 返回使用 | 维护者 7 天使用日记 | 至少有一个快捷动作在 3 个不同日期被实际复用，否则调整入口或删除低价值动作 |
| OCR 质量 | 原图与人工校对文本比较 | 用例和阈值见 F02，不用模型重写后的文本代替 OCR 原始准确率 |
| 模型配置收益 | 一次任务是否需手动切模型/参数 | 明确场景中减少重复设置；未使用的高级项不继续扩充 |

以上均为待验证目标，不是当前成绩。第一轮采用本地手工记录即可，不为收集指标先建设遥测系统；如后续增加统计，默认不上传，不保存输入/答案正文，用户可清除。

不以复制率等单个指标代替用户价值：有人只阅读答案。每周同时记录“为什么没用”“哪里打断流程”。若有愿意试用的新用户，再邀请小范围反馈；本轮没有自动联系任何人。

## 8. 继续与停止条件

- **快捷动作**：如果只是在 Agent 下拉中重复摆放按钮、实际没有减少操作，就收回复杂面板，保留简单常用动作。
- **OCR**：若原型无法稳定打包或目标语言准确率不够，先保留“提取文字”实验入口，不影响现有截图提问。
- **收藏**：先搜索和复制，只有出现大量整理需求后再加标签、文件夹和导出格式。
- **资料问答**：先证明文件附加被持续使用，再建设索引；缺乏可核对引用时不把它作为可靠知识库交付。
- **语音**：不能在目标机器上保持明确的本地处理路径或质量不达标，就暂停，不默认转云转写。
- **写回**：不能确认原应用、原选区仍有效时，只提供复制；未证明可靠性前不扩成自主桌面执行。

## 9. 暂不推进的范围

- 全盘或后台持续上下文采集。
- 团队协作、账号同步、商业化计费、多平台迁移。
- 自动执行 Shell、自动发送邮件/消息、跨应用连续任务执行。
- 为覆盖市场卖点同时接入大量云模型供应商。

若未来定位改变，应重新评估这些方向；目前没有用户研究证据证明它们比现有桌面流程更值得投入。

## 10. 技术可行性依据与局限

以下为 2026-09-13 查阅的官方资料；仅证明接口/平台具备相关能力，不证明项目已接入或达到效果：

- 模型详情返回 capabilities，适合支持能力标签；服务器版本差异仍需处理。[Ollama 模型详情](https://docs.ollama.com/api-reference/show-model-details)
- 模型下载接口支持流式进度，适合 F07 的进度 UI；断开请求是否终止服务端下载需另测。[Ollama 模型下载](https://docs.ollama.com/api/pull)
- 文本 embedding 接口可用于 F09 的本地语义检索实验；检索质量、切片与引用仍属于应用工程。[Ollama Embeddings](https://docs.ollama.com/api/embed)

模型选择、OCR/语音最低系统版本、包体增长和真实内存消耗都应在实现前的短实验中记录，不在本文件中虚构性能结论。
