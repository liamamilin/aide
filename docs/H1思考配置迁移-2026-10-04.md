# H1 思考配置迁移 · 2026-10-04

本轮完成思考模式的类型迁移、动态能力发现、全局与专用配置的 Fluent 选择器，以及请求快照中的设置来源。普通聊天、快捷动作和重新生成仍走唯一运行时；应用入口依然是空工具单轮任务。本轮没有开放 Bash 或自动联网搜索，也没有扩大 H0 的工具准入。

## 设置语义

依据 [Ollama 官方思考控制说明](https://docs.ollama.com/capabilities/thinking)，模型支持的值来自 `/api/show` 的顶层 `thinking.values`；请求可使用精确布尔值、精确档位字符串或 `null`。值未声明、声明无效或所选值不支持时，不猜测档位，不把字符串转成布尔值。

| 设置 | 存储示例 | 发给模型 |
|---|---|---|
| 继承全局设置，仅专用配置可用 | `{"mode":"inherit"}` | 继续解析下一层；不会直接作为 null 发出 |
| 模型默认 | `{"mode":"model_default"}` | `think: null` |
| 关闭 / 开启 | `{"mode":"off"}` / `{"mode":"on"}` | 仅在模型声明该精确布尔值时发送 false / true |
| 模型自定义档位 | `{"mode":"named","level":"xhigh"}` | 仅在当前模型声明完全相同的名字时原样发送 |

优先级仍为本次覆盖 → 动作配置 → Agent 配置 → 全局设置，各字段分别解析。显式“模型默认”会停止继承，不受全局开关影响。能力未知或所选值不支持时，保留请求的设置意图，同时有效 wire 值回落 null；摘要、选择器提示和原有配置回退通知说明实际行为。

带图请求若回退到全局模型，思考设置会按最终模型重新校验；其他生成参数保持原有继承规则。模型、设置模式、设置来源和有效 wire 值在提交时冻结，后续编辑不修改运行中的任务。

## 代码与兼容

- `llm/thinking.py`：不可变 ThinkSetting / ThinkingCapability，精确类型域、结构化序列化和按服务地址 / 模型 / digest 隔离的缓存。
- `llm/service_checks.py`：在已有一次 `/api/show` 请求中读取图片与思考声明，没有新建并行重复的 HTTP 查询路径。
- `services/model_profiles.py`：去掉 `bool(first("think", …))`；旧 profile 的 null 读取为继承，True / False 读取为开关；保存时写入结构化 JSON。
- `settings_manager.py`：兼容旧全局字符串 `True` / `False`，保存结构化 JSON；非法结构读取时回落模型默认并记录日志；全局设置禁止自我继承。
- `llm/events.py` / `chat_client.py` / `run_worker.py`：wire 类型为 bool / str / None；默认参数使用独立内部标记，因此显式 None 不再误读为继承。请求及生成快照新增 think_setting 和 think_source。
- `ui/thinking_selector.py`：使用组件库默认 ComboBox / CaptionLabel。按声明生成选项，服务或模型切换取消旧检查；150ms 合并快速切换，使用完整请求身份忽略过期结果；关闭对话框停止检查。能力未知时只保留已存的待核验选项，不凭空新增开关或档位，请求实际使用模型默认。
- `ui/settings_dialog.py` / `model_profile_dialog.py`：共用选择器，显示对应模型和模型默认值；专用配置编辑区可滚动，底部保存/取消固定可见。

没有增加数据库表或 schema 版本。profile 的旧存储按读取迁移、保存时更新；全局旧值也无需手工重设。设置加载失败不会把未知档位静默变成 False。能力声明只证明取值域，不能证明命名档位的效果差异或工具任务可靠性。
