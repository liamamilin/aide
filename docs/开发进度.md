## 2026-09-13 12:30 — D02 完成

已交付行为：

- 桌面聊天改用 QtNetwork 流式传输。等待首个 token、尚无响应头、已经输出一部分内容时，都可以取消并关闭客户端连接。
- 移除主线程 `wait(5000)`。停止立即恢复输入、发送按钮及悬浮按钮状态，保留已经交付给界面的正文并标明“未完成”，取消内容不作为助手消息保存。
- 图片读取/编码在后台执行；准备期间取消后 UI 立即恢复，后台准备结束时跳过 HTTP。未强制终止图片读取或 QThread，仍运行的线程保留引用直到结束。
- 连接/首次写入预算默认为 10 秒；上传进度或响应头到达后切换为空闲预算，使用请求快照的 `timeout`（默认 120 秒），每次收发数据刷新。Qt 5 没有公开的 reply socket-connected 信号，因此第一阶段包含首次请求写入，不宣称是纯 TCP 握手计时。
- 增量按字节缓存到完整 JSON 行后解码，覆盖中文/emoji 跨包、多个事件同包、CRLF/空行、末行无换行、格式错误、服务错误和异常断流。仅显式 done 成功，终态去重。
- abort、定时器及网络对象释放在同一后台线程完成；正常/取消/错误都清理回复和网络管理器。连续 12 次真实 HTTP 请求后，控制器下无遗留 QThread 对象。
- 结果按请求 ID 校验并使用提交时会话 ID 保存；chunk 按当前 Worker 身份过滤。停止后立即发送、新建会话均会丢弃旧回调；加载历史复用同一取消入口，其完整交互验收仍在 D03。
- 滚动改为 QTimer 排队执行，保留原有 50ms 输出批量刷新，消除 `processEvents()` 引起的结果处理重入。

## 2026-09-14 — F01 中文选区乱码修复
