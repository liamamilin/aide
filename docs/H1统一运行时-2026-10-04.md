# H1 统一运行时检查点 · 2026-10-04

本轮完成 H1 的调度核心，并让普通聊天和快捷动作实际走同一个 `RunWorker / RunLoop`。**H1 整体尚未完成**：动态思考配置、真实执行器的工作区/确认状态、完整存储和工具界面仍按原计划推进；应用仍构建空工具单轮任务，不执行真实 Bash 或自动搜索。

后续的思考配置类型迁移和动态设置现已完成，见 [H1 思考配置迁移检查点](H1思考配置迁移-2026-10-04.md)。下述实现与验证数字保留为首批调度核心记录。

## 实现

| 模块 | 职责 |
|---|---|
| `llm/run_types.py` | 不可变任务、预算、工具 schema/参数契约和状态事件 |
| `llm/run_loop.py` | 唯一顺序循环、消息块、工具结果配对、取消和预算、输入拒绝的有限恢复 |
| `llm/run_worker.py` | 附件准备、Qt 模型传输、线程与 HTTP 生命周期、全局事件序号 |
| `llm/streaming_worker.py` | 仅保留旧名称导入别名，不再含另一套执行实现 |
| `llm/qt_stream.py` | 模型步骤终态；是否接受工具回复由运行时传入，默认拒绝 |

普通聊天、Action 新/当前对话、重新生成继续沿用现有模型配置和消息存储入口。根请求快照不修改；活动步骤有独立身份；控制器用活动步骤过滤事件与保存最终版本，同时保存 initial_request_id 便于关联有限恢复前后的请求。

## 工具范围与终态

角色授权来自只读 `config.AGENT_TOOL_GRANTS`，当前只包含 general_assistant 的 Bash / web_search。授权不放进 Agent 或模型 profile 字段。除此之外还需显式的布尔准入和可用执行器；字符串 `"false"` 等非布尔值不能开启准入。

`origin=action` 优先强制空工具，不受绑定 general_assistant 或传入 registry 的影响。未准入、其他角色、Action 都是单轮任务。`RunWorker` 的应用入口目前只创建这种任务；内部模拟可以注入测试 registry，不能据此声称用户任务已开放。

模型步骤结束与任务结束分离：含工具的正常步骤结束后顺序执行并回填，再发下一步；任务只发一次最终终态。相同参数的独立调用不去重。有 provider ID 时保持调用/结果配对，没有 ID 时仅使用本地 ID 做事件归属，不制造协议 ID。完整调用中已有的 type / function.index 也保留；未验证的参数字符串分片或重复 index 仍按协议错误处理，不猜测合并。回填结构遵循 [Ollama 工具调用接口](https://docs.ollama.com/capabilities/tool-calling)。

未知/未授权工具、参数错误或执行器失败以配对的有限工具错误反馈，可由模型调整方法；执行器异常的原始文本不回填，避免带入原生异常中的凭据。正常工具输出仍保留原文，仅按执行预算裁剪。校验参数不等于 Bash 安全判定：语法、命令分类和确认由 H2 实现。

## 预算、上下文与停止

- 工具任务最多 8 个模型步骤、16 次调用、6 次搜索，活动时间默认 300 秒。返回的整个调用批次先检查剩余额度；不在批次超额时只执行前半部分。最后一个模型步骤若仍请求工具，停止并说明，没有空间继续模型时不做新副作用。
- 每条结果最多 4 KiB UTF-8 字节，截断不切断字符并有标记。多个结果使上下文过大时，先删完整旧消息块，再共同缩短最近完整工具块的摘录，最多缩至每条 256 字节；仍不足则 limited。assistant 调用及全部对应 tool 结果保持同一块。
- system、当前 user 和最近完整工具块保留。输入容量是 UTF-8 字节加消息开销的保守估计，并为已验证的任务输出参数预留空间；不是精确 tokenizer，也不保证未文档化的服务器 shift 行为。普通聊天不按此任务预算偷偷修改原参数或历史。
- 首次 length 直接 limited，保留部分文字，不续写、不执行该步骤调用。取消记忆在启动前也有效，启动前取消跳过图片准备；模型传输期间 abort；步骤和调用之间均复检取消及时间上限。
- 只有明确、带数值的服务端输入超长拒绝允许整个 run 一次恢复，削减完整可选块或结果摘录后重发模型请求。step ID 不变、request ID 更新；不重放已完成工具。HTTP/超时/泛化的 context 字样不触发恢复，第二次拒绝停止。一次恢复会增加一次真实模型请求，计时不中断。
- 模型参数及 schema 每步从不可变快照重新生成，传输适配器修改自己的 payload 不影响下一步。

普通聊天继续使用已有连接/空闲超时，未引入工具任务的 5 分钟总时长限制。RunEvent 的生命周期事件和正文/思考事件共享单调序号，保留完整 run/step/request/conversation 归属。

取消依赖工具执行器配合取消 Event 和截止时间；当前模拟执行器立即返回。真实 Bash 的进程组终止、搜索传输停止、确认等待不计活动时间和 10 分钟过期仍需 H2/H3 实现与验证，本轮未宣称这些已具备。

## 验证

测试覆盖普通无工具、Action 优先级、多步与同轮多调用、无 ID 配对、失败恢复、截断零执行、步骤/总任务终态、预取消和步骤间取消、调用批次预检查、时间上限、完整消息块与 UTF-8 裁剪、显式输入恢复不重放工具、重复/过期事件，以及传输侧修改参数不能影响后续快照。

本机实测使用 H0 同一 Ollama 0.34.3 与 qwen3.5:9b-mlx digest，think=false / num_ctx=8192 / num_predict=1024 / temperature=0，经过真实 Qt 传输和生产 RunWorker：

| 样本 | 结果 | 模型请求 | 工具调用 | 耗时 |
|---|---|---:|---:|---:|
| 简单聊天，只回复 OK | succeeded | 1 | 0 | 0.356 秒 |
| 明确要求网页搜索 Python 文档 | succeeded | 2 | 1 次模拟 web_search | 3.567 秒 |

这是两个冒烟样本，不能作为可靠性或延迟分布。工具返回固定内存数据，未执行真实命令、访问付费搜索或下载新模型。事件与结果保存在 [H1 运行时冒烟](harness-h1/2026-10-04-runtime-smoke.json)。H0 原始准入结论没有扩展。

最终全量回归 **774 passed**，两条既有测试收集警告；其中 RunLoop 新增 50 项，worker/控制器新增 3 项。Ruff、差异检查与四份当前入口文档的本地链接检查通过。

最终 `dist/AI桌面助手.app` 候选版本 1.5.0，约 866MB，沿用原有 `AI Desktop Assistant` 稳定签名。严格签名校验、发布预检、包内 OCR / 英文语音 / 钥匙串桥接诊断、原生界面初始化、schema 4 启动和 schema 0 升级/备份冒烟通过。16 个相关包内模块的字节码与最终源码一致，包含唯一运行时的三个新模块。没有读写真实搜索凭据，没有更新 DMG。旧应用实例需退出后重新打开候选包才会载入本轮变化；本轮不主动替换运行中的实例。
