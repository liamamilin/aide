## 卡片与交互

使用 PyQt-Fluent-Widgets 默认 SimpleCardWidget、文本标签、只读 PlainTextEdit、PrimaryPushButton 和 PushButton，没有自画按钮或额外 QSS。保留现有消息区、流式回答、滚动和输入架构。

- 每个工具调用一张卡片，位于最终回答之前；标题和状态分开，命令/查询始终可查看。等待确认时显示完整原命令、工作目录、判定原因、命令超时、10 分钟倒计时以及执行/拒绝/停止。
- 命令使用纯文本只读编辑器，长内容可滚动/选择，不把 HTML 当富文本解释；执行按钮不设为默认按钮，避免进入窗口后 Enter 自动批准。
- 状态覆盖检查命令、等待确认、提交确认、准备执行、执行中、完成、拒绝、过期、取消和超时。完成卡片撤去执行控件；默认折叠输出，展开查看 stdout/stderr、退出码、耗时与截断说明。
- 没有正文或思考时隐藏空回答占位；收到内容或最终错误后恢复。已有正文不会被工具步骤隐藏。
- 工具任务期间暂停原有失焦自动收起；主动隐藏/关闭窗口停止当前工具任务。普通聊天的隐藏行为保持原样。

## 事件与身份

RunEvent 增加工具名、参数和已按运行预算截断的 ToolOutput，新增 TOOL_UPDATED 用于等待/执行状态；参数和输出不出现在 dataclass repr 中，不新增命令日志。展示结果复用回填模型的摘录；没有新增一套输出处理或执行路径。

RunWorker 提供 confirmation_requested Qt 信号；内部显式工具授权且传入工作区时，可创建接到该信号的 ConfirmationBroker。普通聊天构造函数的工具授权仍为 False。RunLoop 发出状态后由 GUI 主线程更新卡片，阻塞确认和实际进程都留在后台线程。

关键防护是区分**已发出事件的身份**与**后台此刻的活动步骤**：工具结束事件排队到 GUI 时，Worker 可能已经开始下一轮模型。accept_run_event 根据活动 Worker、run/conversation、递增 seq 和已接收的 MODEL_STARTED 步骤校验；不会把合法的前一步结束结果误丢弃。内容流保留原有过滤，两条消费者各自跟踪序号。旧 Worker 发出的事件不能修改新任务。

确认卡片核对 run/conversation/step/request/tool、原命令和目录；点击后立即禁用两个决策按钮，Controller 再核对当前请求、可见窗口和会话，最后由 Broker 校验完整不可变对象、指纹、有效期和单次响应。UI 显示“已批准”必须以 Broker 接受为依据，不根据本地按钮点击假定成功。

停止、清空、切换会话、隐藏窗口和应用关闭会立即废弃卡片、停止计时器并取消任务。迟到的按钮响应或事件不能恢复可执行状态。确认过期由 Broker 截止时间决定，GUI 每秒刷新；即使刷新尚未发生，过期响应也不能批准。拒绝或过期回填工具结果后，模型可继续回答；用户停止则不启动后续模型或工具。
