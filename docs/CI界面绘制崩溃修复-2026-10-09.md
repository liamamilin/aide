# CI 界面绘制崩溃修复

## 故障与证据

[PR #9](https://github.com/liamamilin/aide/pull/9) 的 [CI 第 62 次运行](https://github.com/liamamilin/aide/actions/runs/37918534391) 在 macOS 26.6.2 arm64 上失败。Python 3.11.9 和 3.12.10 均在 Fluent ComboBox 的 `drawSvgIcon` 中出现段错误，退出码 139；3.10 被矩阵的 fail-fast 取消，没有完整结果。

临时 Python 3.11.13 环境安装与 CI 相同的依赖后，完整测试集在第一个测试 `test_number_key_executes_action_with_unchanged_material` 复现相同崩溃。单独运行其文件能够通过。仅把 SIP 12.20.0 改为 12.18.0 后，完整测试仍然崩溃。

pytest-qt 的 `addWidget` 只登记弱引用。测试函数返回后，ActionPanel 的 Python 局部变量释放，窗口可能只剩信号连接形成的循环引用。pytest-qt 随后处理待绘制事件；此时自动 GC 可以回收父窗口，使子下拉框正在使用的绘图设备失效。

在真实 SVG 绘制前强制 `gc.collect()`，并记录窗口的 `destroyed` 信号，可以稳定得到：

```text
WINDOW_DESTROYED_DURING_PAINT
QPaintDevice: Cannot destroy paint device that is being painted
Fatal Python error: Segmentation fault
```

原生崩溃栈位于 `QPainter::save` / `QSvgTinyDocument::draw`。临时禁用自动 GC 的对照能够通过，但最终修复保持 GC 正常运行。

## 修复

- 测试的 qtbot 保留已登记窗口的强引用，覆盖 `addWidget` 和 `add_widget`，原有 `before_close_func` 仍交给 pytest-qt 执行。
- pytest-qt 完成关闭和 `deleteLater` 后，fixture 显式投递 DeferredDelete，再释放强引用，保证原生对象完成销毁。
- 删除 qapp 初始化前一次性的 `gc.collect()`；它只能改变回收时机，不能保证窗口的生命周期。
- 增加有 25 秒进程超时的子进程回归：在真实 SVG 绘制中强制 GC，检查绘制确实发生、窗口绘制期间存活、收尾只销毁一次。移除强引用的对照以 SIGSEGV 失败，保留强引用后两种登记 API 均通过。
- 完整回归暴露 `test_repeated_real_requests_do_not_use_qt_sender_for_worker_identity` 在 `deleteLater()` 投递前立即断言的时序问题。增加最多 3 秒的事件等待，仍检查 20 次请求、20 条回复和所有 worker 原生销毁。
- CI 输出 Python、系统、Qt 和相关依赖版本，并关闭矩阵 fail-fast，让三个版本均独立完成。

## 本地验证

macOS 26.6.2 arm64，Qt 5.15.19、PyQt5 5.15.11、PyQt5-sip 12.20.0、Fluent Widgets 1.11.3、pytest 9.1.1、pytest-qt 4.5.0。

| Python | 完整回归 | 模型准备及窗口生命周期专项 |
| --- | --- | --- |
| 3.10.13 | 1,657 passed，120.42 秒 | 19 passed |
| 3.11.13 | 1,657 passed，69.21 秒 | 19 passed |
| 3.12.10 | 1,657 passed，112.62 秒 | 19 passed |

完整回归各有两条原有的测试类收集警告。3.10、3.12 完整回归开始后加入了 worker 延迟删除等待；这两个版本随后对最终修改另跑专项并通过。3.11 完整回归使用最终代码。CI 版本的 Ruff 检查、源码版本预检和 `git diff --check` 均通过。

修改限于测试及 CI 配置，应用运行代码与依赖约束没有改变。远端 CI 结果以 PR 的实际运行记录为准。
