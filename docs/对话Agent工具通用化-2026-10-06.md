# 对话 Agent 工具通用化

## 使用与授权范围

选择角色和顶栏模型，在输入区点击“工具：关闭”，勾选 Bash、联网搜索或两者，确认工作目录、命令策略和供应商后启用。每次发送前检查当前模型工具能力；失败时保留材料，不切换到另一个模型。

授权只对当前角色、当前对话后续轮次有效。新建、切换或恢复历史对话、切换角色、修改或删除自定义角色、重启应用后，需要重新启用。切换角色时取消旧工具任务和待确认命令，晚到的批准操作不再执行。历史目录和策略可作配置提示，历史记录不会恢复授权。

同一角色/对话切换模型保留工具勾选，取消旧任务，下一次检查并使用新模型。工具模型使用顶栏选择；上下文、采样参数及角色思考/温度/输出覆盖延续 [参数一致性规则](工具模型参数一致性修复-2026-10-05.md)。普通聊天的 profile 模型解析保持原有行为。

设置 → 工具执行中的“允许对话 Agent 启用工具”控制入口，不会自动授权。沿用已有 `general_assistant_tools_enabled` 数据库键，旧版本关闭的偏好仍保持关闭；没有新增权限矩阵或自动继承机制。命令策略、次数、搜索来源设置继续复用。

## 角色与执行

保留原始角色提示词，仅在工具确实授权时附加公共工具规则。普通聊天与快捷动作不接收这一段，也不会构造搜索执行器或读取搜索凭据。所有 Action 保持无工具单轮，即使在已启用工具的当前对话执行。

公共规则要求明确读取文件或联网查证时先用工具取得材料，再按原角色要求回答。首次真实 9B 验收中，翻译角色仅把 `cat note.txt` 输出为代码，没有执行；补充该规则后六种角色全部完成真实工具闭环。这不意味着任何角色或模型都保证正确调用工具，也不把工具调用成功当成答案质量保证。

重新执行工具答案需确认、重新检查当前模型及原任务角色。切换到另一个角色后无法重新执行旧角色任务，需切回原角色并重新授权。普通答案的重新生成始终不调用工具。

实现涉及统一工具注册 `CHAT_TOOL_NAMES`、显式布尔准入、绑定角色的 `TaskAuthorization`、捕获角色与参数的异步检查、工具任务取消，以及保留实际角色/模型的审计。未增加另一套执行器；工作目录仍不是系统沙箱，复杂命令按现有策略确认。
