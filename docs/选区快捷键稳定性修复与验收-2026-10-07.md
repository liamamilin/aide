# 选区快捷键稳定性修复与验收

日期：2026-10-07。范围：Command + Control + L 选区读取及共享的截图快捷键监听；保留产品功能和界面结构。

## 发现与修复

| 问题 | 影响 | 改动 |
|---|---|---|
| 快捷键触发后固定延迟 100ms，未检查修饰键是否松开 | 用户仍按着 Control 时模拟 Command+C，可能形成错误组合 | 进入复制状态机后每 20ms 异步检查修饰键，最长等待 1500ms；快照读取后、AppleScript 回退前再次检查 |
| 忽略系统长按重复标志，控制器每次重新开始延迟 | 多次触发或持续推迟选区读取 | NSEvent 忽略 `isARepeat`；控制器合并等待中与捕获中的触发 |
| 设置页、设置加载及监听器校验不同 | 格式通过但实际监听错误键；未知键原来静默落到 A | 统一原生解析器；拒绝未知键、多个主键、重复修饰键和缺失主键；支持 `<space>`、`<f1>` 等命名键；加载非法旧设置时保留默认/当前有效值 |
| 数字 7 / 8 / 9 的虚拟键码错误 | 自定义这些快捷键时触发其他键 | 按本机 Apple HIToolbox Events.h 修正为 26 / 28 / 25 |
| 额外 Shift / Option 仍匹配，已停止监听的排队回调可调用新回调 | 误触发、重注册后的旧事件影响新操作 | 精确比较四类快捷键修饰标志，忽略 Caps Lock；停止使旧一代回调失效 |

超时或读取修饰键状态失败时，使用现有宠物/菜单栏非阻塞反馈；清空本次待执行动作或朗读意图，不粘贴空内容、不执行旧意图。没有强制释放用户按键，也没有记录用户键盘内容。现有剪贴板条件恢复、较新用户复制优先和取消逻辑保留。

这些是代码中已发现并修复的失效原因，不能据此断言此前每次失效都来自同一个问题。系统权限、其他应用阻止复制、密码输入框或其他快捷键冲突仍需要对应场景验证。

## 自动化与原生验收

- 回归覆盖：未知键/命名键、真实数字键码、长按、额外修饰键、旧回调、等待超时、取消、状态探测失败、读取快照期间重新按键、控制器合并与失败清理、设置页拒绝非法快捷键及旧设置加载。
- 新增免费隔离诊断 `selection_hotkey`：真实 Cocoa Qt 窗口、`NSApplication.sendEvent_` 分发真实 NSEvent 对象，经过本地监听与控制器进入实际 SelectionCaptureTask；按住修饰键超过 180ms 时仍能处理 Qt 事件且没有复制；放开后混合中文/英文正确进入输入框。
- 诊断只使用 `NSPasteboard.pasteboardWithUniqueName()` 的独立剪贴板，验证原始文本和 HTML 字节恢复；复制动作与修饰键状态使用可控 fixture。不注册全局监听，不读取用户剪贴板，不向其他应用注入系统按键，不调用模型、钥匙串或搜索。
- 源码原生验收：[报告](harness-h6/selection-hotkey-source-2026-10-07.json)。冻结包原生验收：[报告](harness-h6/selection-hotkey-packaged-2026-10-07.json)，同样通过；两份报告都明确没有验证物理键盘和跨应用真实复制。

## 发布前还需真实体验

1. 从浏览器、文本编辑器、聊天应用分别选择中英文，按 Command + Control + L，稍慢松开修饰键，再连续操作；确认输入、快捷动作及原剪贴板。
2. 不选文字、按住快捷键超过 1.5 秒、触发后立即退出、应用前台/后台切换，确认反馈与下一次可恢复。
3. 验证 Command + Control + S 截图、取消框选、睡眠唤醒、切换输入法与真实多屏/Spaces。
4. 最后验证覆盖安装和系统权限。上述隔离验收未验证物理键盘输入、其他应用的真实复制处理或 TCC 授权；不自动把这些项目标记为完成。

参考：[Apple NSEvent 事件监听说明](https://developer.apple.com/library/archive/documentation/Cocoa/Conceptual/EventOverview/MonitoringEvents/MonitoringEvents.html)、[合并会话修饰键状态](https://developer.apple.com/documentation/coregraphics/cgeventsourcestateid/combinedsessionstate)。本地监听涵盖自身应用，全局监听涵盖其他应用；诊断明确只安装本地监听。
